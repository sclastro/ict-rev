# 模擬頁旁白：交接說明

給下一個 session：用戶要為 `site/sim/cpu-cycle.html` 加入旁白（粵語及英文），在模擬頁加「旁白：粵語／English／關閉」切換，自動播放時每步等錄音播完才前進。

## 已決定

- 粵語旁白用書面語，以粵語讀出；下面 40 段為定稿（用戶已批准）。英文旁白稍後照樣起草，交用戶過目。
- 曾試聲音複製（CosyVoice、GPT-SoVITS），聲調不夠準，用戶決定改用 Microsoft Azure 語音服務的香港粵語聲線（zh-HK：HiuMaanNeural、HiuGaaiNeural、WanLungNeural），不模仿用戶聲音。先讓用戶試聽幾種聲線再選。
- 金鑰由用戶存於環境設定：`AZURE_SPEECH_KEY`、`AZURE_SPEECH_REGION`（例如 `eastasia`）。端點：`https://<region>.tts.speech.microsoft.com/cognitiveservices/v1`（SSML，`X-Microsoft-OutputFormat` 用 MP3）。不要把金鑰寫入 repo。
- 錄音預先生成，放 `site/sim/audio/zh/<編號>.mp3`（建站時隨 `site/sim` 複製到 `docs/sim`）。學生輸入的數字每次不同，旁白不讀出這些數值。
- 字母詞（PC、IR、MAR、MDR、ACC、CU、ALU、SSD、CPU）逐個字母讀；RAM 可讀作單字。
- 需留意的正讀：位址、位元的「位」wai6；代表的「表」biu2；這個的「這」ze2；鍵盤的「盤」pun4；部件的「件」gin6；轉換為、成為的「為」wai4。Azure 若讀錯，可用 SSML 調整或換同音字。

## 編號與步驟的對應

- 提取階段：指令 0 用 F1–F4；指令 1–6 用 F1s–F4s；「精簡提取階段」模式用 FB。
- 譯碼：D0–D6 對應指令 0–6。
- 執行：IN 指令用 I1a/I1b（等待輸入）、I2、I3、I4a/I4b；LOAD 用 L1–L3；ADD 用 A1–A4；STORE 用 S1–S3；OUT 用 O1–O3；HALT 用 H1。
- 準備 P1–P3，總結 Z1。

## 粵語旁白定稿

## 一、準備（3 段）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| P1 | 準備第 1 步 | 加法程式現時存放在 SSD，也就是輔助儲存設備。輔助儲存設備屬非易失性，關機後內容仍然保留，但存取速度較慢，CPU 不能直接從這裏提取指令。 |
| P2 | 準備第 2 步 | 使用者開啟程式後，操作系統經匯流排系統，把程式的機器碼由 SSD 複製到主記憶體位址零至六，並預留位址十、十一、十二存放變數 a、b、c。程式必須先載入主記憶體，CPU 才可以執行。 |
| P3 | 準備第 3 步 | 操作系統把程式第一個指令的位址，即位址零，放入程式計數器 PC。留意 PC 存放的是下一個指令的位址，不是指令本身。 |

## 二、提取階段（9 段）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| F1 | 指令 0 提取① | 提取階段開始。控制器把程式計數器 PC 中的位址，複製到記憶體位址寄存器 MAR。MAR 存放的是位址，不是數據。 |
| F2 | 指令 0 提取② | MAR 的位址經位址匯流排送往主記憶體；同時，控制器經控制匯流排發出「讀取」信號。 |
| F3 | 指令 0 提取③ | 主記憶體找出該位址的內容，即一個指令，經數據匯流排送回 CPU，存入記憶體數據寄存器 MDR。 |
| F4 | 指令 0 提取④ | 指令由 MDR 複製到指令寄存器 IR；同時 PC 加一，指向下一個指令。 |
| F1s | 指令 1 至 6 提取① | 提取下一個指令：PC 的位址複製到 MAR。 |
| F2s | 指令 1 至 6 提取② | 位址經位址匯流排送往主記憶體，控制匯流排發出「讀取」信號。 |
| F3s | 指令 1 至 6 提取③ | 指令經數據匯流排送到 MDR。 |
| F4s | 指令 1 至 6 提取④ | 指令複製到 IR，PC 加一。 |
| FB | 精簡模式的提取 | 提取階段：PC 的位址經 MAR 和位址匯流排送往主記憶體，指令經數據匯流排送回 MDR，再複製到 IR；PC 加一。 |

## 三、譯碼階段（7 段）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| D0 | 指令 0：IN 10 | 譯碼階段。控制器解讀 IR 中的指令：前四個位元是操作碼，代表「輸入」；後四個位元是操作數，代表位址十，即變數 a。 |
| D1 | 指令 1：IN 11 | 譯碼：操作碼代表「輸入」，操作數代表位址十一，即變數 b。 |
| D2 | 指令 2：LOAD 10 | 譯碼：操作碼代表「載入」，操作數代表位址十。這個指令把變數 a 的值載入累加器。 |
| D3 | 指令 3：ADD 11 | 譯碼：操作碼代表「加」，操作數代表位址十一。這個指令把變數 b 的值與累加器的數值相加。 |
| D4 | 指令 4：STORE 12 | 譯碼：操作碼代表「儲存」，操作數代表位址十二。這個指令把累加器的數值存入變數 c。 |
| D5 | 指令 5：OUT 12 | 譯碼：操作碼代表「輸出」，操作數代表位址十二，即變數 c。 |
| D6 | 指令 6：HALT | 譯碼：操作碼零零零零代表「停止」，這個指令不需要操作數。 |

## 四、執行及儲存階段（20 段）

### 指令 0、1：IN（輸入）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| I1a | 指令 0 執行① | 執行階段。控制器經控制匯流排向鍵盤發出「讀取」信號，等待使用者輸入。請輸入第一個數，然後按「確定」。 |
| I1b | 指令 1 執行① | 控制器再次向鍵盤發出「讀取」信號。請輸入第二個數，然後按「確定」。 |
| I2 | 指令 0、1 執行② | 鍵盤把按鍵轉換為二進制數，經數據匯流排送入 MDR。 |
| I3 | 指令 0、1 儲存① | 儲存階段。控制器把操作數的位址放入 MAR，經位址匯流排送往主記憶體，並經控制匯流排發出「寫入」信號。 |
| I4a | 指令 0 儲存② | MDR 中的數值經數據匯流排寫入主記憶體位址十，成為變數 a 的值。 |
| I4b | 指令 1 儲存② | MDR 中的數值經數據匯流排寫入位址十一，成為變數 b 的值。 |

### 指令 2：LOAD（載入）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| L1 | 執行① | 執行階段。控制器把位址十放入 MAR，經位址匯流排送往主記憶體，並發出「讀取」信號。 |
| L2 | 執行② | 主記憶體把變數 a 的值經數據匯流排送到 MDR。 |
| L3 | 執行③ | 數值由 MDR 複製到累加器 ACC。LOAD 指令不需要 ALU 運算。 |

### 指令 3：ADD（加）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| A1 | 執行① | 執行階段。控制器把位址十一放入 MAR，經位址匯流排送出，並發出「讀取」信號。 |
| A2 | 執行② | 變數 b 的值經數據匯流排送到 MDR。 |
| A3 | 執行③ | 控制器指示算術及邏輯運算部件 ALU 執行加法，ACC 和 MDR 的數值同時送入 ALU。 |
| A4 | 儲存 | 儲存階段。ALU 算出結果，存入累加器 ACC。ALU 的運算結果通常存放在 ACC。 |

### 指令 4：STORE（儲存）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| S1 | 執行① | 執行階段。控制器把位址十二放入 MAR，並把 ACC 的數值複製到 MDR，準備寫入主記憶體。 |
| S2 | 執行② | 位址經位址匯流排送往主記憶體，控制器經控制匯流排發出「寫入」信號。 |
| S3 | 執行③ | MDR 的數值經數據匯流排寫入位址十二，成為變數 c 的值。至此完成「c 等於 a 加 b」這一行程式。 |

### 指令 5：OUT（輸出）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| O1 | 執行① | 執行階段。控制器把位址十二放入 MAR，經位址匯流排送出，並發出「讀取」信號。 |
| O2 | 執行② | 變數 c 的值經數據匯流排送到 MDR。 |
| O3 | 執行③ | 控制器經控制匯流排通知顯示器，MDR 的數值經數據匯流排送往顯示器，屏幕顯示計算結果。 |

### 指令 6：HALT（停止）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| H1 | 執行 | 執行停止指令。控制器不再提取下一個指令，程式結束，控制權交回操作系統。 |

## 五、總結（1 段）

| 編號 | 使用於 | 旁白 |
|---|---|---|
| Z1 | 總結 | 總結一下：四行程式翻譯成七個機器碼指令，CPU 為每個指令各經歷一次提取、譯碼和執行。PC 指向下一個指令；MAR 和 MDR 負責與主記憶體交換位址和數據；IR 存放正在執行的指令；ALU 負責運算，結果存入 ACC；三種匯流排分別傳送位址、數據和控制信號。 |
