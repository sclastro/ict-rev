程式測試和除錯Program Testing and Debugging

Program Testing and Debugging程式測試和除錯
建議課時 11 小時Suggested time: 11 hours課本第 7 至 8 章Textbook Ch. 7–8

4.1課程要求

應用數據驗證設計合適的測試數據；了解並描述程式錯誤的類型（語法、邏輯和運行時），解釋它們發生的原因並除錯；辨別邊界案例；從執行步數及資源運用的角度，比較以不同算法解決同一問題的優劣。

4.2數據驗證

有效性檢驗以預設的規則檢查輸入是否合理，拒絕不合理的數據。常見的檢驗：

檢驗 檢查甚麼 例子
存在檢查 必填欄位不是空白 姓名、數量不可留空
範圍檢查 數值在指定範圍內 分數 0 至 100；心跳率 40 至 200
長度檢查 字符數目符合要求 密碼 8 至 16 個字符；用戶編號剛好 7 個字符
類型檢查 數據屬正確的類型 年齡必須是整數
格式檢查 數據符合指定的格式 產品編號為「YYYY-CAT-NNN」
固定值檢查（查找表） 數據是預設清單中的其中一個 班別只可以是 2A、2B、2C、2D
校驗碼 以其他位數計算出的校驗碼與輸入的校驗碼相同 用戶名稱最後一位是校驗碼

數據校驗則檢查輸入的數據是否與來源相符，例如要求重新輸入密碼，或請用戶核對螢幕上顯示的資料。有效性檢驗只能保證數據合理，不能保證數據正確：學生在下拉式選單選了別人的班別，仍會通過檢驗。

⚠ 〔2025 卷一甲第 31 題〕「輸入 N；當 N < 0 執行：輸入 N」中，使用循環的目的是甚麼？

✔ 數據有效性檢驗：輸入負數時要求重新輸入，直至數值合理。

✘ 選「數據校驗」。這個循環只檢查 N 是否合理，沒有與來源比對。

⚠ 〔2025 卷一乙 7(c)〕數據庫表格中 CL 儲存學生的班別。建議一項比格式檢查更有效的有效性檢驗。

✔ 固定值檢查：只接受學校現有的班別（例如 2A、2C、3D）。格式檢查只能確保「一個數字加一個字母」，無法拒絕不存在的班別如 7Z。

✘ 考評局指出，只有少數考生答「固定值檢查」；部分考生誤以為同一個數據值可以同時套用多項檢驗，因而列出多項。

校驗碼

〔2025 卷一乙 9〕用戶名稱由級別 F（1 至 6）、班別 C（A 或 B）、學號 N（1 至 40）和校驗碼 D 組成。計算方法：S ← F + N；如果 C = "B"，S ← S × 3；D 是 (S / 10) 的餘數。

用戶名稱 檢查 結果
4B115 F = 4、C = B、N = 11；(4 + 11) × 3 = 45，45 除以 10 的餘數是 5，與 D 相同 有效
2C180 班別 C 不存在 無效
  • 系統最多支援 6 × 2 × 40 = 480 名學生。
  • 校驗碼的限制：不同的錯誤可能得出相同的校驗碼。例如 1A245 誤輸入為 1A145，(1 + 24) 和 (1 + 14) 除以 10 的餘數同樣是 5，系統偵測不到學號錯誤。
  • 考評局指出，不少考生判斷用戶名稱有效時沒有列出校驗碼的計算過程，因而失分。

4.3設計測試數據

測試數據要能找出錯誤，不能只用「一定會成功」的數據。

類別 意思 例子（年齡須介乎 18 至 60，包括兩端）
正常數據 範圍內的典型數據，程式應接受 30、45
邊界數據 在範圍邊緣或剛超出邊緣的數據，最容易出錯 17、18、60、61
不合理數據 範圍以外的數據，程式應拒絕 −5、120
錯誤類型的數據 類型不符的輸入 "二十"、空白

測試計劃應列出每項測試數據的目的和預期結果，執行後與實際結果比較。

測試數據 目的 預期結果
30 正常數據 接受
18 下限邊界 接受
17 剛低於下限 拒絕
60 上限邊界 接受
61 剛高於上限 拒絕

⚠ 〔2025 卷一甲第 30 題〕「如果 (age <= 11) OR (age >= 60) 則輸出 "Discount!!" 否則輸出 "No discount!!"」，哪組年齡最適合測試這個算法？

✔ 10、11、12、59、60、61：兩個條件的邊界及其兩旁都測試到。93% 考生答對。

✘ 選 1、2、3、4、5：全部只測試同一個分支。

〔2023 卷一甲第 6 題〕「如果 MARKS >= 50 則輸出 "PASS" 否則輸出 "FAIL"」，合適的測試值是 99、0、50：同時測試合格、不合格和邊界 50。只有不合格數值（−10、30、40）或只有合格數值（100、99、86）的組合都不合適。

〔樣本試卷卷一甲第 36 題〕「如果 A > 5 則 B ← 10 否則 B ← 20」的邊界案例是輸入 5 和 6。10 和 20 是輸出，不是邊界案例。

⚠ 〔2024 卷一乙 4(a)〕陣列 A 有六個整數。ALG1 驗證「所有整數都是正數」，ALG2 驗證「整數按升序排列」。說明以下兩組無效測試數據的目的：個案 1：3、5、5、3、8、5；個案 2：−1、−1、3、5、5、8。

✔ 個案 1 全是正數但不按升序，用來檢查 ALG2 能否驗證整數按升序排列。個案 2 已按升序但有負數，用來檢查 ALG1 能否驗證所有整數都是正數。

✘ 考評局指出，只有少數考生把答案與題目的算法聯繫起來，多數只籠統地寫「測試錯誤數據」。

〔2023 卷一乙 3(d)〕為排序子程式從三組數據中選兩組測試。三組各有特點：含負數和零（−3、−1、4、0、7）、已排序（1、2、3、4、5）、含重複值（1、1、3、3、5）。任選兩組，並說明各自測試的是甚麼情況。

4.4程式錯誤的類型

錯誤類型 意思 發生原因 例子（Python）
語法錯誤 程式違反程式語言的規則，不能翻譯和執行 打錯關鍵字、遺漏符號、縮排錯誤 if x > 0 欠冒號；print("Hi) 欠引號；if a = b:
邏輯錯誤 程式能執行，但結果與預期不符 算法或公式錯誤 平均值除以 5 而不是 3；range(1, n) 少做一次；> 寫成 >=
運行時錯誤 程式在執行期間出錯而終止 執行時遇到無法完成的運算 除以零；存取不存在的索引；int("abc")；求負數的平方根
  • 語法錯誤由翻譯程式（編譯器或解譯器）在執行前或執行至該行時指出，最容易發現。
  • 邏輯錯誤不會產生錯誤訊息，翻譯程式無法得知程式員想要的公式，只能靠測試數據和空運行找出。
  • 運行時錯誤可能只在某些輸入下才出現，例如輸入 0 作除數。

〔樣本試卷卷一甲第 30 題〕算法要計算某算式的平方根。輸入的 B 令該算式的值為負數時，程式在執行期間無法求平方根，屬運行時錯誤。

⚠ 在 Python 中，把 print 誤寫成 prnt 要到執行該行時才出錯（NameError），所以一般歸類為運行時錯誤；在 C++ 中，編譯器在編譯時就會指出同樣的錯誤，屬語法錯誤。答題時要配合題目所用的語言和情境說明。

4.5除錯方法

方法 做法
空運行及追蹤表 以人手逐行執行，記錄變量值，找出與預期不符的一步
加入輸出語句 在可疑位置暫時輸出變量的值，觀察程式的執行情況
使用 IDE 的除錯工具 設定中斷點令程式在指定行暫停，逐步執行並檢查變量的值
逐個模組測試 先獨立測試每個模組，確定正確後才組合

預防運行時錯誤：計算前先檢查數據，例如除數為 0 時不作除法，或以循環要求用戶重新輸入。Python 的 try、except 可以攔截運行時錯誤，避免程式終止，屬延伸內容。

divisor = int(input("輸入除數："))
while divisor == 0:
    print("除數不可以是 0")
    divisor = int(input("輸入除數："))
print(100 / divisor)

4.6比較算法

解決同一問題可以有多個算法。比較時，從兩方面考慮：

方面 看甚麼
執行步數 完成工作所需的比較、計算或迭代次數；步數越少，執行越快
資源運用 所需的記憶體，例如額外的變量或陣列

提早停止可減少步數

〔樣本試卷卷一乙 4(c)〕ALG1 在數據檔的所有字串中搜尋某字串，每次都檢查全部字串。ALG1 效率欠佳，因為即使目標在前面已找到，仍要比較餘下所有字串；以旗標配合前測循環，找到後即可停止。

數據影響步數：同一算法處理不同的數據，步數可以相差很遠。

〔2023 卷一乙 3(b)〕某排序子程式處理五個數：已按升序排列的 2、3、5、7、9 毋須交換（0 次）；按降序排列的 9、7、5、3、2 則要交換 10 次。

比較次數：〔2025 卷一乙 8(b)(i)〕「Smax ← 1；設 i 由 2 至 N：如果 JS[i] > JS[Smax] 則 Smax ← i」的判斷執行 N − 1 次，即 4 次。

例子：判斷陣列中雙數是否最少佔一半

ALG1
C ← 0
設 i 由 1 至 N
    如果 (A[i] / 2) 的餘數 = 0 則
        C ← C + 1
如果 C >= N / 2 則 輸出 "E" 否則 輸出 "O"

ALG2
C ← 0
i ← 1
當 (i <= N) AND (C < N / 2) 執行
    如果 (A[i] / 2) 的餘數 = 0 則
        C ← C + 1
    i ← i + 1
如果 C >= N / 2 則 輸出 "E" 否則 輸出 "O"

N = 8，A 為 6、4、2、8、1、3、5、7 時，ALG2 數到第四個雙數就停止，只判斷 4 次；ALG1 必定判斷 8 次。若雙數始終不足一半，例如 1、3、5、7、9、2、4、6，兩者都要判斷 8 次。兩個算法所用的記憶體相近。

⚠ 增加記憶體不會減少算法的比較次數。算法慢是因為步數多時，要改善算法本身。

速度與記憶體的取捨

做法 速度 記憶體
計算後立即輸出每個結果 每次輸出都要時間 毋須額外陣列
先把結果存入陣列，最後一次過處理 可重複使用結果，毋須重新計算 要額外陣列
以臨時變量交換兩個值 三次賦值 多一個變量

選擇算法時，還要考慮程式是否容易理解和維護。較短、較清晰的算法，日後修改時較少出錯。

4.7自我檢測

1. 寫出有效性檢驗與數據校驗的分別，各舉一例。

有效性檢驗以規則檢查數據是否合理，例如範圍檢查心跳率須介乎 40 至 200。數據校驗檢查數據是否與來源相符，例如要求重新輸入密碼，或請用戶核對顯示的資料。

2. 網上表格要求輸入 8 至 16 個字符的密碼（包括 8 和 16）。寫出四個合適的邊界測試數據（以字符數目表示）。

7、8、16、17 個字符。

3. 考試分數須介乎 0 至 100（包括兩端）。設計一組測試數據，包括正常、邊界和不合理數據。

例如 −1（不合理）、0（邊界）、50（正常）、100（邊界）、101（不合理）。

4. 指出以下各情況屬哪類錯誤：(a) 平均值除以 5 而不是 3 (b) if 語句末尾欠冒號 (c) 用戶在要求整數的欄位輸入 "abc"，程式終止 (d) 循環中以 0 作除數

(a) 邏輯錯誤；(b) 語法錯誤；(c) 運行時錯誤；(d) 運行時錯誤。

5. 為甚麼 IDE 通常無法自動找出邏輯錯誤？

邏輯錯誤的程式符合語法、可以執行，IDE 無法得知程式員想要的公式或結果。只有以測試數據比較實際和預期結果，或以空運行追蹤，才能發現。

6. 猜數字遊戲要求 GUESS 介乎 1 至 100（包括兩端），程式寫 if GUESS > 1 and GUESS < 100:。指出錯誤，並建議一個能發現此錯誤的測試值。

> 和 < 不包括 1 和 100，程式會拒絕有效的邊界值。應改為 if GUESS >= 1 and GUESS <= 100:。測試值 1 或 100 可以發現這個錯誤。

7. 停車場有 50 個車位。為測試「車位已滿」的條件，寫出一個正常、一個邊界和一個不合理的測試數據（已泊車輛數目）。

正常：49；邊界：50；不合理：51。（其他合理答案亦可）

8. 某系統的用戶編號最後一位是校驗碼。校驗碼有甚麼作用？舉出它的一項限制。

作用：以其他位數計算校驗碼並與輸入的校驗碼比較，偵測輸入錯誤，例如打錯某一位。限制：不同的錯誤可能得出相同的校驗碼，部分錯誤因而偵測不到。

9. 解釋為甚麼找到目標後即停止的搜尋算法，一般比檢查所有元素的算法有效率。在甚麼情況下兩者步數相同？

找到目標後毋須比較餘下的元素，減少比較次數。若目標在最後一個位置或根本不存在，兩者都要檢查所有元素，步數相同。

10. 有人建議增加電腦的記憶體，令線性搜尋處理一百萬個數據時快一點。你同意嗎？

不同意。線性搜尋慢是因為要逐一比較大量數據，增加記憶體不會減少比較次數。應改善算法，例如找到後即停止。

11. 以 Python 編寫程式，要求用戶輸入介乎 1 至 30 的參加人數，輸入不合理時要求重新輸入。 
n = int(input("參加人數："))
while n < 1 or n > 30:
    print("人數須介乎 1 至 30")
    n = int(input("參加人數："))
12. 算法 A 處理 1000 個數據需 0.5 秒、一百萬個數據需 480 秒；算法 B 分別需 0.8 秒和 90.5 秒。高流量的系統應選哪一個？

算法 B。它處理大量數據時所需的時間增長得慢得多，雖然處理少量數據時稍慢。
