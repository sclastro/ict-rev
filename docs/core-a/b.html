單元 A · 課題 b

數據組織及數據控制

Data Organisation and Data Control
建議課時 4 小時課本第 2 章

2.1課程要求

辨別數據分級組織中的數據、記錄、欄、檔案和數據庫；解釋記錄的組織、儲存及提取，比較直接存取和順序存取；討論數據控制的重要性；闡述以有效性檢驗及奇偶檢測偵測誤差，以驗證及有效性檢驗防止誤差。

2.2為甚麼要數據控制

人手輸入常見三類錯誤：

錯誤 意思 例子
數據來源錯誤 提供者給出錯誤資料 顧客報錯電話號碼
轉錄錯誤 讀錯或輸入錯 把數字「0」輸入成字母「O」
位置調換錯誤 相鄰字符次序對調 把 16 輸入成 61

錯誤的輸入必然產生錯誤的輸出，稱為「無用輸入，無用輸出」（GIGO）。數據控制的目的是確保輸入數據準確，常用方法是數據有效性檢驗和數據驗證。

2.3數據有效性檢驗（Data Validation）

把輸入數據與預先定義的規則比較，確保數據合理及有效。

檢查 作用 例子
完整性檢查（必填欄位檢查，presence check） 必要欄位不可留空 學生編號不可空白
欄位長度檢查（length check） 字符數目正確 香港電話號碼必須是 8 位
範圍檢查（range check） 數值在指定範圍內 測驗分數介乎 0 至 100
固定值檢查（fixed value check） 只接受清單內的值 班別只可以是 A、B、C、D
格式檢查（format check） 符合指定格式 電郵地址須含「@」
類型檢查（type check） 數據類型正確 分數必須是數字
檢查數位（check digit） 以公式計算並附在數據末端，用來自我核對 ISBN、香港身份證號碼

有效性檢驗只能保證數據「合理」，不能保證數據「正確」。 例如把 78 分誤輸成 87 分，範圍檢查不會察覺。

⚠ 〔2025 卷一乙 7(c)〕建議一項比格式檢查更有效的有效性檢驗，用於班別欄 CL。

✔ 答案：固定值檢查（班別只能是學校實際有的班別）。考生表現「差」，很多人不認識固定值檢查。說不出術語但描述正確，亦可得分。

✘ 一位第 5 級考生答「範圍檢查」；班別是文字，不適合用範圍檢查。

另有考生誤以為答案可以同時堆砌多項檢查。題目要求一項，就答最合適的一項。

⚠ 〔2024 卷一乙 1(a)(iii)〕D 欄只會是 1 或 0，除了完整性檢查外，建議一項有效性檢驗。

✔ 固定值檢查／類型檢查／範圍檢查（0 至 1 之間的整數）。

✘ 格式檢查、完整性檢查、欄位長度檢查均不接受。

⚠ 〔2025 卷一乙 7(a)(i)〕建議比文字框更好的表單元素，用來輸入班別。

✔ 下拉式選單或單選按鈕，因為只提供有效的班別選項，確保輸入的數據有效、合理。

✘ 部分考生說這樣可以「確保輸入正確」，概念錯誤：學生仍然可能選錯班別。

2.4檢查數位（Check Digit）

檢查數位由數據其餘部分按固定公式計算得出，附在數據末端。系統收到數據後重新計算，若結果與附帶的檢查數位不同，即表示數據無效。

計算示例（自擬）：某會員編號由四位數字加一個檢查數位組成，規則是「首四位數字按權重 4、3、2、1 相乘後相加，取除以 10 的餘數」。

驗證 3517-8：3×4 + 5×3 + 1×2 + 7×1 = 12 + 15 + 2 + 7 = 36，36 mod 10 = 6。附帶的檢查數位是 8，兩者不同，所以編號無效。

⚠ 〔2025 卷一乙 9(b)〕判斷用戶名稱是否有效，並指出檢查數位的局限。

✔ 判斷有效或無效必須附完整算式，包括取餘數（mod）的步驟，並說明結論的理由。例如「(11 + 4) × 3 mod 10 = 5，與檢查數位相同，所以有效」可得 2 分；算式不完整只得 1 分；沒有解釋得 0 分。判斷無效時亦要說明原因，例如班別「C」不存在。

✔ 局限：兩個不同的輸入可能得出相同的檢查數位，這類錯誤無法偵測。必須舉出具體例子並列出兩組算式，才可得滿分。

✘ 不接受：「計算費時」「只能檢查數字，不能檢查字母」「檢查數位只有 0 至 9」。

2.5奇偶檢測（Parity Check）

用於數據傳輸或複製後檢查位元錯誤，例如在網絡傳送數據包，或由 RAM 把數據寫入硬碟。

  • 偶檢測：加上檢驗位後，「1」的總數為偶數。
  • 奇檢測：加上檢驗位後，「1」的總數為奇數。

例子：數據 1011 0010 有四個「1」。偶檢測的檢驗位是 0，傳送 1011 0010 0；奇檢測的檢驗位是 1，傳送 1011 0010 1。

局限：若有偶數個位元同時出錯，例如兩個位元互換或同時翻轉，「1」的總數的奇偶性不變，錯誤無法偵測。

⚠ 〔2024 卷一乙 4(a)(ii)〕在 15 位元的圖像位元樣式末端加上一個偶數檢驗位。

✔ 只在整個位元樣式的末端加一個檢驗位，共 16 位元。

✘ 較弱的考生每三個位元加一個檢驗位，或把檢驗位放在最前。

⚠ 〔2023 卷一乙 4(d)(i)〕數據傳輸時可能有一個位元出錯，簡述如何檢查。

✔ 加上奇偶檢驗位；使用校驗和（checksum）；傳送兩次並比較。

✘ 不少考生答檢查數位、欄位長度檢查、類型檢查，這些是輸入時的有效性檢驗，不是傳輸錯誤檢測。考評局特別提醒要分清「錯誤檢測」與「有效性檢驗」。

2.6數據驗證（Data Verification）

檢查輸入的數據是否與原始來源一致。

方法 做法 例子
輸入數據兩次 同一人輸入兩次，電腦比較兩次結果 設定新密碼時輸入兩次
雙重數據輸入 兩人各自把同一份文件輸入電腦，電腦比較兩個檔案 臨床研究數據
比較 數據有效性檢驗 數據驗證
目的 確保數據合理、符合規則 確保數據與原始來源一致
能否發現「輸入了合理但錯誤的值」 不能 可以

✔ 「重新輸入密碼」屬數據驗證，不是有效性檢驗〔樣本試卷甲部第 3 題；改編自 2025 卷一甲第 3 題〕。 ✔ 香港身份證號碼 A123456(7) 誤輸為 A123455(7)，檢查數位和輸入數據兩次都能發現錯誤；範圍檢查不能〔改編自 2025 卷一甲第 6 題〕。

2.7數據分級組織

數據（位元、字節）→ 欄 → 記錄 → 數據表（檔案）→ 數據庫

層次 意思 例子
欄（Field） 記錄中的一項特定資料，是用戶存取數據的最小單位 出生日期
記錄（Record） 一組相關的欄，描述一個實體 一位學生的全部資料
數據表／檔案（Table / File） 結構相同的記錄的集合 全校學生資料表
數據庫（Database） 相關數據表的集合，以關鍵碼連結 學生資料表、成績表、借書表

在數據表中，一列（row）是一個記錄，一欄（column）是一個欄位〔2024 簡報提醒考生弄清楚〕。

2.8主關鍵碼（Primary Key）

主關鍵碼用來唯一識別數據表中的每個記錄，數值必須獨一無二而且不可為空值。

  • 沒有單一欄位符合要求時，可以用兩個或以上欄位組成複合主關鍵碼，例如 CLASS + CLASS_NO。
  • 應選最少欄位的組合，不要加入多餘欄位。
  • 選擇時要考慮情境。流動電話號碼可以作為會員數據表的主關鍵碼，卻不適合學生數據表，因為部分學生沒有電話。
  • 香港身份證號碼雖然獨一無二，但屬敏感個人資料，一般不宜作主關鍵碼。

⚠ 〔2024 卷一乙 1(b)〕員工出勤記錄表 ATTEND（每位員工每日一個記錄）。

(i) 為何 NAME 不能作為關鍵欄？✔「它不是獨一無二的」。考評局提醒要理解題目情境：表中每位員工每日都有一個記錄，同一個名字必然重複出現。

(ii) 寫出主關鍵碼。✔ EID + DATE（DATE + EID 或「EID, DATE」亦接受）。✘ EID + DATE + NAME（不是最少欄位）；只寫 EID；「EID and DATE」。考評局建議用「+」連接。

⚠ 〔2024 卷一乙 1(b)(iv)〕為何毋須把試算表中的總結資料（每人出席總日數）轉入數據庫？

✔ 它們是衍生數據（由原始數據計算得來），儲存會造成數據冗餘；需要時可用 SQL 查詢重新產生。

⚠ 〔樣本試卷乙部 8(c)〕有學生缺席測驗，建議在分數欄儲存「ABS」或 0。

✔ 「ABS」與數字欄位的數據類型不符；0 會與真正考 0 分的學生混淆。若改用 -1 代表缺席，計算平均分等之前必須先剔除 -1。

2.9數據庫管理系統的基本功能

數據庫管理系統（DBMS）用來管理數據庫結構，以及儲存、整理和提取數據。例子：MySQL、Microsoft SQL Server、Oracle（伺服器）；Microsoft Access、LibreOffice Base（桌面）。

基本操作包括新增、瀏覽、修改及刪除記錄；主要功能包括篩選、排序、表單、查詢和報表，詳見課題 d：數據操縱和分析的 4.9 節。

2.10檔案存取模式

模式 典型媒體 特點
順序存取（sequential） 磁帶 必須由頭依次讀取；尋找時間長而且難以預計；成本低，適合備份
直接存取（direct） 硬碟、光碟 讀寫頭直接移到目標位置；尋找時間短而且可預計
隨機存取（random） 固態硬碟（SSD） 任何位置幾乎即時存取；尋找時間固定而且極短

課程文件要求比較直接存取與順序存取；課本另把 SSD 列為隨機存取。

2.11自我檢測

1. 數據 0110 1110 以奇檢測傳送，檢驗位應是甚麼？

數據有五個「1」，已是奇數，所以檢驗位是 0，傳送 0110 1110 0。

2. 某網上表格要求輸入出生日期。建議兩項不同的有效性檢驗。

格式檢查（須為 DD/MM/YYYY）；範圍檢查（年份須介乎合理範圍，例如不可遲於今天）。亦可答完整性檢查。

3. 圖書館數據表 LOAN 記錄每次借書（欄位：學生編號、書本編號、借出日期）。為甚麼「學生編號 + 書本編號」不一定適合作主關鍵碼？

同一學生可以在不同日子再借同一本書，兩個記錄的「學生編號 + 書本編號」會重複。應加入借出日期，組成「學生編號 + 書本編號 + 借出日期」。
