### 考評局反覆強調的答題原則

以下幾點見於 2023 至 2025 年每一份簡報，適用於全卷，單元 A 尤其明顯。

1. **答案要扣緊題目情境。** 評卷員不會猜測考生的意思；答案只複述常識、過於籠統或照抄題目，一律不給分。
2. **要求兩個答案時，兩個答案必須屬於不同類別。** 同一類別的答案只得 1 分。例如「在不同網站核對」和「向老師查證」都屬「多方核對」。
3. **用專業術語。** 修讀 ICT 的考生應以技術角度作答，例如寫「固定值檢查」而不是「檢查是否正確」。
4. **多分題有層次。** 第一分通常容易取得，其後各分要求更深入的理解。
5. **計算題要列式和寫單位。** 缺少單位會失去答案分。
6. **比較題要用比較級。** 例如寫「較高的時鐘頻率」而不是「高時鐘頻率」〔2025 卷一乙 5(a)〕。
7. **用報考語文作答。** 中文卷以中文作答；函數名稱、SQL 指令及常見縮寫（如 SSL、RSI）可照寫英文。

## 一、資訊處理簡介（課題 a）

### 1.1 課程要求

識別資訊系統的組成部分；區分七個資訊處理過程；分辨數據與資訊；辨識文本、數字、圖像、音效、視像等數據類型；界定資訊時代，討論知識型社會中資訊素養的重要性。

### 1.2 資訊系統的五個組成部分

資訊系統把輸入的**數據**轉換為輸出的**資訊**，過程可以是人手或自動。

| 組成部分 | 意思 | 例子：學校小食部電子點餐系統 |
|---|---|---|
| 系統功能（System function） | 系統要達成的目的 | 讓學生預先點餐及付款 |
| 數據（Data） | 系統處理的原始事實，是最不可或缺的部分 | 學生編號、食物編號、數量 |
| 流程（Procedure） | 把輸入轉為輸出的步驟或程式 | 接收訂單、計算金額、通知廚房 |
| 科技（Technology） | 硬件、軟件、網絡及設備 | 平板電腦、數據庫伺服器、Wi-Fi |
| 從業員（Personnel） | 終端用戶及資訊系統專業人員 | 學生、小食部職員、系統分析員 |

資訊系統專業人員的職責：

| 職位 | 主要職責 |
|---|---|
| 系統分析員 | 研究用戶需求，設計新系統或改良現有系統 |
| 程式員 | 編寫及測試程式碼 |
| 數據庫管理員 | 管理和整理系統內的數據 |
| 網絡管理員 | 監察及維護網絡的運作、保安和效能 |
| 技術員 | 為硬件、軟件和網絡提供技術支援及維修 |

✔ **輸出主要由輸入數據和處理邏輯決定。** 改用另一部電腦或由另一位程式員開發，只會影響處理速度或效率，不會改變同一輸入的結果〔改編自 2025 卷一甲第 2 題〕。

### 1.3 七個資訊處理過程（資訊生命周期）

**數據收集 → 數據整理 → 數據儲存 → 數據處理 → 數據分析 → 數據傳送 → 數據演示**

| 過程 | 目的 | 電腦方式例子 | 非電腦方式例子 |
|---|---|---|---|
| 收集 | 為特定目的取得數據 | 網上問卷、感應器 | 訪問、紙本問卷、觀察 |
| 整理 | 按特定格式排列數據，準備處理 | 用數據庫排序、分組 | 人手分類問卷 |
| 儲存 | 存放數據以供日後提取 | 雲端儲存、固態硬碟 | 檔案夾、紙本記錄 |
| 處理 | 運算或轉換數據，產生有用資訊 | 以 SQL 計算平均分 | 人手計算缺席人數 |
| 分析 | 從處理結果中找出趨勢或規律 | 統計軟件、趨勢分析 | 開會討論統計結果 |
| 傳送 | 把結果送到另一系統或使用者 | 電郵、內聯網 | 郵寄、速遞 |
| 演示 | 以合適形式展示資訊 | 圖表、網頁、簡報 | 紙本報告 |

⚠ 「處理」與「分析」容易混淆。處理是**計算或轉換**，例如求總分；分析是**解讀**，例如比較兩班表現差異的原因。

### 1.4 數據與資訊

- **數據（Data）**：未經處理、本身不具意義的原始事實，例如 80、65、72 三個分數。
- **資訊（Information）**：經處理後具有意義、有助決策的結果，例如「平均分 72.3，全班合格」。

✔ 判斷時問自己：「它是經計算或整理得來的嗎？能否直接用來作決定？」平均分、等級、排名都是資訊；個別分數是數據。

常見數據類型：文本、數字、圖像、音效、視像。各類型的檔案格式見第三部分。

### 1.5 資訊時代、知識型社會與資訊素養

**資訊時代**：電腦成為處理及管理資訊不可或缺的工具；寬頻和流動網絡令資訊能隨時隨地以低成本取得。促成資訊時代的科技包括運算技術進步、寬頻及無線網絡普及、互聯網與雲端服務，以及人工智能、大數據和物聯網。

**知識型社會**：以知識為最重要的資產，重視創新和終身學習。關鍵要素是電腦、通訊網絡及具備資訊素養的人。

**資訊素養**：具備資訊素養的人能夠判斷所需資訊的性質和範圍，有效地取得資訊，評估資訊來源，運用資訊完成任務和創造新知識，並以合乎道德和法律的方式使用資訊。

> ⚠ **〔2023 卷一乙 1(d)(i)〕建議兩個方法核實網上資訊。**
> ✔ 可接受：與不同來源互相核對；查閱權威來源；檢查資料的發佈日期。
> ✘ 不給分：只寫「核實來源」「檢查資料」（題目本身就是這樣問）；寫「檢查網站有沒有數碼證書或 SSL」（這屬於網絡保安，不屬於資訊可靠性）。
> 評卷時按類別給分，類別包括完整性、準確性、權威性、客觀性、時效性、合法性。兩個答案須屬不同類別。

### 1.6 自我檢測

<details><summary>1. 某學會把會員報名表的資料輸入電腦並列印會員名單。「輸入報名資料」和「列印名單」分別屬哪個資訊處理過程？</summary>

輸入報名資料屬**數據儲存**；列印名單屬**數據演示**。若題目強調把紙本資料轉成電子形式，亦可視為數據收集的一部分，作答時須扣緊題目描述。
</details>

<details><summary>2. 某同學說：「我每天上網三小時，所以我具備資訊素養。」試評論。</summary>

不同意。資訊素養指能判斷所需資訊、評估來源可靠性，並以合乎道德的方式運用資訊；上網時間長短不代表具備這些能力。
</details>

## 二、數據組織及數據控制（課題 b）

### 2.1 課程要求

辨別數據分級組織中的數據、記錄、欄、檔案和數據庫；解釋記錄的組織、儲存及提取，比較直接存取和順序存取；討論數據控制的重要性；闡述以有效性檢驗及奇偶檢測偵測誤差，以驗證及有效性檢驗防止誤差。

### 2.2 為甚麼要數據控制

人手輸入常見三類錯誤：

| 錯誤 | 意思 | 例子 |
|---|---|---|
| 數據來源錯誤 | 提供者給出錯誤資料 | 顧客報錯電話號碼 |
| 轉錄錯誤 | 讀錯或輸入錯 | 把數字「0」輸入成字母「O」 |
| 位置調換錯誤 | 相鄰字符次序對調 | 把 16 輸入成 61 |

錯誤的輸入必然產生錯誤的輸出，稱為**「無用輸入，無用輸出」（GIGO）**。數據控制的目的是確保輸入數據準確，常用方法是**數據有效性檢驗**和**數據驗證**。

### 2.3 數據有效性檢驗（Data Validation）

把輸入數據與預先定義的規則比較，確保數據**合理及有效**。

| 檢查 | 作用 | 例子 |
|---|---|---|
| 完整性檢查（必填欄位檢查，presence check） | 必要欄位不可留空 | 學生編號不可空白 |
| 欄位長度檢查（length check） | 字符數目正確 | 香港電話號碼必須是 8 位 |
| 範圍檢查（range check） | 數值在指定範圍內 | 測驗分數介乎 0 至 100 |
| 固定值檢查（fixed value check） | 只接受清單內的值 | 班別只可以是 A、B、C、D |
| 格式檢查（format check） | 符合指定格式 | 電郵地址須含「@」 |
| 類型檢查（type check） | 數據類型正確 | 分數必須是數字 |
| 檢查數位（check digit） | 以公式計算並附在數據末端，用來自我核對 | ISBN、香港身份證號碼 |

**有效性檢驗只能保證數據「合理」，不能保證數據「正確」。** 例如把 78 分誤輸成 87 分，範圍檢查不會察覺。

> ⚠ **〔2025 卷一乙 7(c)〕建議一項比格式檢查更有效的有效性檢驗，用於班別欄 CL。**
> ✔ 答案：**固定值檢查**（班別只能是學校實際有的班別）。考生表現「差」，很多人不認識固定值檢查。說不出術語但描述正確，亦可得分。
> ✘ 一位第 5 級考生答「範圍檢查」；班別是文字，不適合用範圍檢查。
> 另有考生誤以為答案可以同時堆砌多項檢查。題目要求一項，就答最合適的一項。

> ⚠ **〔2024 卷一乙 1(a)(iii)〕D 欄只會是 1 或 0，除了完整性檢查外，建議一項有效性檢驗。**
> ✔ 固定值檢查／類型檢查／範圍檢查（0 至 1 之間的整數）。
> ✘ 格式檢查、完整性檢查、欄位長度檢查均不接受。

> ⚠ **〔2025 卷一乙 7(a)(i)〕建議比文字框更好的表單元素，用來輸入班別。**
> ✔ 下拉式選單或單選按鈕，因為只提供有效的班別選項，**確保輸入的數據有效、合理**。
> ✘ 部分考生說這樣可以「確保輸入正確」，概念錯誤：學生仍然可能選錯班別。

### 2.4 檢查數位（Check Digit）

檢查數位由數據其餘部分按固定公式計算得出，附在數據末端。系統收到數據後重新計算，若結果與附帶的檢查數位不同，即表示數據無效。

**計算示例（自擬）**：某會員編號由四位數字加一個檢查數位組成，規則是「首四位數字按權重 4、3、2、1 相乘後相加，取除以 10 的餘數」。

驗證 **3517-8**：3×4 + 5×3 + 1×2 + 7×1 = 12 + 15 + 2 + 7 = 36，36 mod 10 = 6。附帶的檢查數位是 8，兩者不同，所以編號**無效**。

> ⚠ **〔2025 卷一乙 9(b)〕判斷用戶名稱是否有效，並指出檢查數位的局限。**
> ✔ 判斷有效或無效必須附**完整算式**，包括取餘數（mod）的步驟，並說明結論的理由。例如「(11 + 4) × 3 mod 10 = 5，與檢查數位相同，所以有效」可得 2 分；算式不完整只得 1 分；沒有解釋得 0 分。判斷無效時亦要說明原因，例如班別「C」不存在。
> ✔ 局限：**兩個不同的輸入可能得出相同的檢查數位**，這類錯誤無法偵測。必須舉出具體例子並列出兩組算式，才可得滿分。
> ✘ 不接受：「計算費時」「只能檢查數字，不能檢查字母」「檢查數位只有 0 至 9」。

### 2.5 奇偶檢測（Parity Check）

用於**數據傳輸或複製後**檢查位元錯誤，例如在網絡傳送數據包，或由 RAM 把數據寫入硬碟。

- **偶檢測**：加上檢驗位後，「1」的總數為偶數。
- **奇檢測**：加上檢驗位後，「1」的總數為奇數。

例子：數據 1011 0010 有四個「1」。偶檢測的檢驗位是 0，傳送 1011 0010 **0**；奇檢測的檢驗位是 1，傳送 1011 0010 **1**。

局限：若有**偶數個位元同時出錯**，例如兩個位元互換或同時翻轉，「1」的總數的奇偶性不變，錯誤無法偵測。

> ⚠ **〔2024 卷一乙 4(a)(ii)〕在 15 位元的圖像位元樣式末端加上一個偶數檢驗位。**
> ✔ 只在**整個位元樣式的末端**加一個檢驗位，共 16 位元。
> ✘ 較弱的考生每三個位元加一個檢驗位，或把檢驗位放在最前。

> ⚠ **〔2023 卷一乙 4(d)(i)〕數據傳輸時可能有一個位元出錯，簡述如何檢查。**
> ✔ 加上奇偶檢驗位；使用校驗和（checksum）；傳送兩次並比較。
> ✘ 不少考生答檢查數位、欄位長度檢查、類型檢查，這些是**輸入時的有效性檢驗**，不是傳輸錯誤檢測。考評局特別提醒要分清「錯誤檢測」與「有效性檢驗」。

### 2.6 數據驗證（Data Verification）

檢查輸入的數據是否與**原始來源一致**。

| 方法 | 做法 | 例子 |
|---|---|---|
| 輸入數據兩次 | 同一人輸入兩次，電腦比較兩次結果 | 設定新密碼時輸入兩次 |
| 雙重數據輸入 | 兩人各自把同一份文件輸入電腦，電腦比較兩個檔案 | 臨床研究數據 |

| 比較 | 數據有效性檢驗 | 數據驗證 |
|---|---|---|
| 目的 | 確保數據合理、符合規則 | 確保數據與原始來源一致 |
| 能否發現「輸入了合理但錯誤的值」 | 不能 | 可以 |

✔ 「重新輸入密碼」屬**數據驗證**，不是有效性檢驗〔樣本試卷甲部第 3 題；改編自 2025 卷一甲第 3 題〕。
✔ 香港身份證號碼 A123456(7) 誤輸為 A123455(7)，**檢查數位**和**輸入數據兩次**都能發現錯誤；範圍檢查不能〔改編自 2025 卷一甲第 6 題〕。

### 2.7 數據分級組織

**數據（位元、字節）→ 欄 → 記錄 → 數據表（檔案）→ 數據庫**

| 層次 | 意思 | 例子 |
|---|---|---|
| 欄（Field） | 記錄中的一項特定資料，是用戶存取數據的最小單位 | 出生日期 |
| 記錄（Record） | 一組相關的欄，描述一個實體 | 一位學生的全部資料 |
| 數據表／檔案（Table / File） | 結構相同的記錄的集合 | 全校學生資料表 |
| 數據庫（Database） | 相關數據表的集合，以關鍵碼連結 | 學生資料表、成績表、借書表 |

在數據表中，一**列（row）**是一個記錄，一**欄（column）**是一個欄位〔2024 簡報提醒考生弄清楚〕。

### 2.8 主關鍵碼（Primary Key）

主關鍵碼用來**唯一識別**數據表中的每個記錄，數值必須**獨一無二**而且**不可為空值**。

- 沒有單一欄位符合要求時，可以用兩個或以上欄位組成**複合主關鍵碼**，例如 CLASS + CLASS_NO。
- 應選**最少欄位**的組合，不要加入多餘欄位。
- 選擇時要考慮情境。流動電話號碼可以作為會員數據表的主關鍵碼，卻不適合學生數據表，因為部分學生沒有電話。
- 香港身份證號碼雖然獨一無二，但屬敏感個人資料，一般不宜作主關鍵碼。

> ⚠ **〔2024 卷一乙 1(b)〕員工出勤記錄表 ATTEND（每位員工每日一個記錄）。**
> (i) 為何 NAME 不能作為關鍵欄？✔「它不是獨一無二的」。考評局提醒要理解題目情境：表中每位員工每日都有一個記錄，同一個名字必然重複出現。
> (ii) 寫出主關鍵碼。✔ **EID + DATE**（DATE + EID 或「EID, DATE」亦接受）。✘ EID + DATE + NAME（不是最少欄位）；只寫 EID；「EID and DATE」。考評局建議用「+」連接。

> ⚠ **〔2024 卷一乙 1(b)(iv)〕為何毋須把試算表中的總結資料（每人出席總日數）轉入數據庫？**
> ✔ 它們是**衍生數據**（由原始數據計算得來），儲存會造成**數據冗餘**；需要時可用 SQL 查詢重新產生。

> ⚠ **〔樣本試卷乙部 8(c)〕有學生缺席測驗，建議在分數欄儲存「ABS」或 0。**
> ✔ 「ABS」與數字欄位的數據類型不符；0 會與真正考 0 分的學生混淆。若改用 -1 代表缺席，計算平均分等之前必須先剔除 -1。

### 2.9 數據庫管理系統的基本功能

數據庫管理系統（DBMS）用來管理數據庫結構，以及儲存、整理和提取數據。例子：MySQL、Microsoft SQL Server、Oracle（伺服器）；Microsoft Access、LibreOffice Base（桌面）。

基本操作包括新增、瀏覽、修改及刪除記錄；主要功能包括篩選、排序、表單、查詢和報表，詳見第四部分 4.9 節。

### 2.10 檔案存取模式

| 模式 | 典型媒體 | 特點 |
|---|---|---|
| 順序存取（sequential） | 磁帶 | 必須由頭依次讀取；尋找時間長而且難以預計；成本低，適合備份 |
| 直接存取（direct） | 硬碟、光碟 | 讀寫頭直接移到目標位置；尋找時間短而且可預計 |
| 隨機存取（random） | 固態硬碟（SSD） | 任何位置幾乎即時存取；尋找時間固定而且極短 |

課程文件要求比較**直接存取**與**順序存取**；課本另把 SSD 列為隨機存取。

## 三、數據表示（課題 c）

### 3.1 課程要求

區分模擬及數碼數據並說明兩者轉換的情境；解釋資訊科技為何使用數碼數據，包括位元數目與組合數量的關係；十進制、二進制、十六進制互換；以二進制補碼表示負整數；二進制加減及溢出誤差（最多 2 字節）；ASCII、大五碼、國標碼、統一碼（無須背誦個別編碼）；多媒體元素數碼化及常見檔案格式比較（bmp、png、jpg、wav、mp3、avi、mpeg4、txt、docx、odt、pdf）。

### 3.2 模擬數據與數碼數據

| 比較 | 模擬數據 | 數碼數據 |
|---|---|---|
| 表示方式 | 連續的信號（平滑波形） | 離散的數值（0 和 1） |
| 複製 | 每次複製都會失真 | 可完全複製 |
| 傳輸 | 錯誤率較高 | 錯誤率較低，可偵測錯誤 |
| 儲存 | 效率低，媒體體積大 | 效率高，媒體細小 |
| 分析處理 | 難以搜尋及重組 | 電腦容易處理、搜尋、編輯 |

**數碼化**包括兩個步驟：

1. **取樣（sampling）**：每隔固定時間從連續信號取得一個樣本。
2. **量化（quantization）**：把每個樣本轉換為指定級數的數碼編碼。

數碼化必然損失部分原始資訊。提高取樣率和位元解像度，可以令結果更接近原本的信號，但仍不能完全相同。

轉換設備：模擬數碼轉換器（ADC）把模擬信號轉為數碼，例如用麥克風錄音時由音效卡轉換；數碼模擬轉換器（DAC）把數碼信號轉為模擬，例如揚聲器播放音樂。掃描器把相片數碼化；打印機和顯示器把數碼圖像轉為人眼看到的模擬形式。

### 3.3 位元數目與組合數量

**n 個位元可以表示 2ⁿ 個不同組合。** 3 個位元可表示 8 種顏色；要表示 26 個英文字母，最少需要 5 個位元（2⁴ = 16 不足，2⁵ = 32 足夠）。

> ⚠ **〔2024 卷一乙 4(a)(ii)(2)〕5 × 3 的黑白點陣顯示板，可以顯示多少個不同圖像？**
> ✔ 2¹⁵ = 32 768。✘ 不少考生答「15」，混淆了「位元數目」與「組合數目」。

> ⚠ **〔2024 卷一乙 4(b)(ii)〕記錄其中一點的位置（如 B3）需要多少位元？**
> ✔ 5 位元（行 A 至 E 需 3 位元，列 1 至 3 需 2 位元）；或 4 位元（15 個位置，2⁴ = 16 ≥ 15）。
> ✘ 較弱考生答 1 或 2 位元，理由是「點只有黑白兩色」，忽略了題目問的是**位置**。

### 3.4 數系轉換

| 轉換 | 方法 |
|---|---|
| 二／十六進制 → 十進制 | 每個數位乘以位值後相加 |
| 十進制 → 二／十六進制 | 不斷除以 2（或 16），由下而上讀餘數 |
| 二進制 → 十六進制 | 由右至左每四位一組，逐組轉換 |
| 十六進制 → 二進制 | 每個數位轉成四個位元 |

例子：2C7₁₆ = 2 × 256 + 12 × 16 + 7 = **711₁₀**；二進制為 **10 1100 0111₂**（2 → 0010，C → 1100，7 → 0111，去掉前導零）。

十六進制常用於程式員與電腦系統之間的溝通，因為比二進制簡短，而且與二進制轉換容易。

### 3.5 數據單位

| 單位 | 換算 |
|---|---|
| 1 字節（B） | 8 位元（b） |
| 1 KB | 1024 B |
| 1 MB | 1024 KB |
| 1 GB | 1024 MB |
| 1 TB | 1024 GB |

**字（word）**是 CPU 一次處理的數據單位，現今電腦的字長一般是 64 位元。

### 3.6 整數的二進制表示

| 表示法 | n 位元的範圍 | 8 位元範圍 |
|---|---|---|
| 無符號整數 | 0 至 2ⁿ − 1 | 0 至 255 |
| 符號及值 | −(2ⁿ⁻¹ − 1) 至 2ⁿ⁻¹ − 1 | −127 至 127 |
| 二進制補碼 | −2ⁿ⁻¹ 至 2ⁿ⁻¹ − 1 | −128 至 127 |

- **符號及值**：最左位元是符號位（0 正、1 負），其餘位元表示數值。缺點是零有兩種表示（0000 0000 和 1000 0000）。
- **二進制補碼**：每個整數只有一種表示，現代電腦普遍採用。

**求負數的二進制補碼（以 −45，8 位元為例）**

1. 寫出 45 的二進制：0010 1101
2. 所有位元取反（一補碼）：1101 0010
3. 加 1：**1101 0011**

驗算：−128 + 64 + 16 + 2 + 1 = −45 ✔

**把補碼轉回十進制**：最左位元是 1 表示負數，重複「取反再加 1」求出數值，再加上負號。另一個方法是把最左位元當作 −2ⁿ⁻¹，其餘照常相加。

記住特殊樣式：8 位元最大正數 0111 1111（127），最小負數 1000 0000（−128），−1 是 1111 1111〔樣本試卷甲部第 5 題〕。

### 3.7 二進制加減及溢出誤差

計算結果超出位元所能表示的範圍，就會出現**溢出誤差（overflow error）**。

- **無符號整數**：最高位產生進位（加法），或需要向最高位之外借位（減法），即溢出。
- **二進制補碼**：兩個**同號**的數相加，結果卻變成**異號**，即溢出。兩個異號數相加永不溢出，最左的進位直接捨棄。

例子（8 位元二進制補碼）：100 + 50

```
  0110 0100   (100)
+ 0011 0010   ( 50)
-----------
  1001 0110   符號位變成 1
```

兩個正數相加得出負數，出現溢出誤差（150 大於 127）。

✔ 減法可改寫成加上負數，例如 −33 − 65 = −33 + (−65)。
✔ 「1110 1111 + 0001 0000」和「1101 1111 + 0010 0001」哪個結果是 0000 0000？逐位計算並捨棄最左進位，答案是後者〔改編自 2025 卷一甲第 4 題〕。

### 3.8 字符編碼

| 編碼 | 字符範圍 | 每字符字節數 |
|---|---|---|
| ASCII | 英文字母、數字、標點（7 位元，128 個字符） | 1 |
| 大五碼（Big5） | 繁體中文及 ASCII 字符 | 1 至 2 |
| 國標碼（GB） | 簡體中文及 ASCII 字符 | 1 至 2 |
| 統一碼（Unicode，常用 UTF-8） | 全球現存語言的字符 | 1 至 4（英文 1，中文一般 3） |

- 字符集越大，每個字符所需位元越多。
- 同一個中文字在不同編碼的編碼值不同。用錯編碼開啟檔案，會出現亂碼。
- UTF-8 與 ASCII 向後兼容，英文字符在兩者中編碼相同。
- 檔案大小例子：純文字「ICT 資訊」以 UTF-8 儲存佔 4 + 2 × 3 = 10 字節；以大五碼儲存佔 4 + 2 × 2 = 8 字節。

> ⚠ **〔2023 卷一甲第 13 題〕** 只有約一半考生答對「統一碼用來表示英文及其他語言的字符」。常見誤解：以為大五碼只包含中文（其實包含 ASCII 字符）；以為使用哪種字符集由操作系統或瀏覽器決定。

### 3.9 多媒體：文本

| 格式 | 特點 |
|---|---|
| TXT | 純文字，不含格式；檔案最小，任何文字編輯器都可開啟 |
| RTF | 支援基本文字格式 |
| DOCX | 支援完整格式、圖像、表格；須用相容的文書處理器 |
| ODT | 國際開放標準的文書格式 |
| PDF | 固定版面，在任何設備顯示效果相同；一般不可直接編輯；可設密碼、限制列印和複製 |

> ⚠ **〔2025 卷一甲第 9 題〕** 在網上發佈文章時選 PDF 而不選 HTML 的原因：**PDF 提供較好的文件保護**。只有 52% 考生答對，不少人選了對 HTML 有利的選項。
> ✔ PDF 勝於 TXT：保留文字格式、可加入圖片。ODT 勝於 PDF：較容易編輯〔樣本試卷乙部第 5 題〕。

### 3.10 多媒體：圖像

**點陣圖（bitmap）**由像素組成，畫質取決於**解像度**和**色彩深度**。

| 色彩深度 | 顏色數目 | 用途 |
|---|---|---|
| 1 位元 | 2 | 黑白文件、傳真 |
| 8 位元 | 256 | 灰度圖像、索引顏色 |
| 24 位元 | 約 1680 萬 | 真實顏色相片 |

**向量圖形（vector graphic）**以數學公式描述線條和形狀，放大後不失真，檔案通常較小，適合標誌、圖示、線條圖。常見格式：SVG、AI、EPS、WMF。

| 格式 | 壓縮 | 透明背景 | 動畫 | 主要用途 |
|---|---|---|---|---|
| BMP | 不壓縮 | ✘ | ✘ | 保留最高畫質，檔案大 |
| JPG | 有損 | ✘ | ✘ | 數碼相片、網頁 |
| PNG | 無損 | ✔ | ✘ | 網頁圖像、需要透明背景的圖像 |
| GIF | 無損（只有 256 色） | ✔ | ✔ | 簡單動畫 |
| RAW | 不壓縮 | ✘ | ✘ | 相機原始數據，供後期製作 |
| TIFF | 有損或無損 | ✔ | ✘ | 印刷出版 |
| HEIC | 有損或無損 | — | — | 智能電話相片，檔案細而畫質高 |
| WebP | 有損或無損 | ✔ | ✔ | 網頁及流動應用程式 |

**有損壓縮**刪除部分數據以縮小檔案，刪除的數據**無法還原**；**無損壓縮**可完全還原原始數據。

**長寬比（aspect ratio）**是闊度與高度的比例，例如 4:3、16:9。改變長寬比顯示圖像或影片，會令畫面**變形（失真）**，或在兩側出現黑邊。

> ⚠ **〔2024 卷一甲第 3 題〕** 「ai」是圖像檔案格式（Adobe Illustrator 向量圖形），只有約三分之一考生知道。
> ⚠ **〔2023 舊課程卷二丙第 1 題〕** 點陣圖的缺點應寫「檔案較大」「放大後畫質下降」；寫「起格仔」「圖片失真、不清楚」不給分。只有不足五分之一考生能描述適合用向量圖形的情境，例如需要以不同尺寸顯示的標誌。只有約三分之一考生知道有損壓縮會令部分數據永久刪除。
> ⚠ **〔2024 舊課程卷二丙第 1 題〕** GIF 的優點是支援透明背景、動畫、無損壓縮；缺點是最多 256 色。較弱考生錯誤地比較了 GIF 與 JPG 的檔案大小。
> ⚠ **〔2023 舊課程卷二丙第 1 題；2024 舊課程卷二丙第 1 題〕** 影片長寬比與屏幕不同：會出現黑邊或畫面變形。不到 10% 考生答到黑邊及解決方法（用軟件調整長寬比，或按正確解像度拍攝）。

### 3.11 多媒體：音效

數碼音效的質素取決於**取樣率**（每秒樣本數，單位 Hz）、**位元解像度**（每個樣本的位元數）和**聲道數目**（單聲道 1、立體聲 2、7.1 環繞聲 8）。

| 格式 | 特點 |
|---|---|
| WAV | 不壓縮，音質最好，檔案大 |
| MP3 | 有損壓縮，約為原檔十分之一 |
| AAC | 有損壓縮，同位元率下音質較 MP3 好，支援多聲道 |
| FLAC | 無損壓縮 |
| MIDI | 只記錄樂譜指令，不含錄音；檔案極小；不能儲存人聲 |

> ⚠ **〔2023 舊課程卷二丙第 2 題〕** 只用來儲存音效的格式是 AAC、MP3、WAV。較弱考生誤以為 MP4 也是純音效格式；MP4 是視像格式。

### 3.12 多媒體：視像

未壓縮視像的大小取決於**幀大小**（每幀的像素闊度 × 高度）、**色彩深度**、**幀率**（fps）和**長度**。

| 格式 | 特點 |
|---|---|
| AVI | 常見的未壓縮視像格式，畫質高，檔案大 |
| MP4（MPEG-4） | 有損壓縮，檔案細；支援串流、字幕；HTML5 支援 |
| MPEG | 用於 DVD 等光碟 |
| MOV | Apple 開發的視像格式 |
| WebM | 開放源碼，網頁常用 |

提高幀率，動作更流暢，但檔案更大。

### 3.13 檔案大小與傳輸時間計算

**公式總表**

| 對象 | 公式（結果單位為位元） |
|---|---|
| 未壓縮圖像 | 闊度像素 × 高度像素 × 色彩深度 |
| 未壓縮音效 | 取樣率 × 位元解像度 × 聲道數目 × 時間（秒） |
| 未壓縮視像 | 闊度像素 × 高度像素 × 色彩深度 × 幀率 × 時間（秒） |
| 壓縮音效或視像 | 位元率（bps）× 時間（秒） |
| 傳輸時間 | 檔案大小（位元）÷ 頻寬（bps） |
| 壓縮比 | 原檔大小 ÷ 壓縮後大小 |

**單位原則**

- 字節（B）轉位元（b）：**× 8**；位元轉字節：÷ 8。
- **檔案大小**（KB、MB、GB）：用 1024 換算。
- **頻寬及位元率**（kbps、Mbps、Gbps）：**一律用 1000 換算**，1 Mbps = 1 000 000 bps。
- 計算時先統一單位，最後寫上答案單位。

**例一：未壓縮圖像**
1600 × 1200 像素、24 位元色彩深度的 BMP：
1600 × 1200 × 24 ÷ 8 = 5 760 000 B；÷ 1024 ÷ 1024 ≈ **5.49 MB**

**例二：未壓縮音效**
立體聲、44.1 kHz、16 位元、3 分鐘：
44 100 × 16 × 2 × 180 = 254 016 000 b；÷ 8 ÷ 1024 ÷ 1024 ≈ **30.28 MB**

**例三：壓縮音效**
位元率 256 kbps、3 分鐘：
256 × 1000 × 180 = 46 080 000 b；÷ 8 ÷ 1024 ÷ 1024 ≈ **5.49 MB**
（壓縮檔大小只與位元率和時間有關，與取樣率、聲道數目無關。）

**例四：傳輸時間**
以 50 Mbps 上載 3 GB 影片：
3 × 1024³ × 8 ÷ (50 × 1 000 000) ≈ **515.4 秒**（約 8.6 分鐘）

> ⚠ **〔2025 卷一乙 3(a)〕每張相片 5 MB，上載頻寬 100 Mbps，估算上載 200 張的最短時間。**
> ✔ (200 × 5 × 8) ÷ 100 = **80 秒**。檔案大小用 1024 換算（約 84 秒）亦接受。
> ✘ 沒有把字節轉為位元（× 8）；答案沒有單位；**頻寬用 1024 換算**。表現只屬「尚可」。

> ⚠ **〔2023 卷一乙 5(b)(ii)〕200 個 2 KB 記錄，以 10 Mbps 傳送。**
> ✔ 200 × 2 × 1024 × 8 ÷ (10 × 1 000 000) ≈ 0.33 秒。
> ✘ 評卷參考列出的錯誤：檔案大小用 1000（0 分）；頻寬用 1024（0 分）；少計一個零；漏乘 200；欠單位。

> ⚠ **〔2024 舊課程卷二丙第 1、2 題〕** 圖像大小計算時，少數考生把色彩深度寫成 256（顏色數目），應用 **8 位元**；計算位元率時用了 1024 而不是 1000。

✔ 考評局提醒：寫出公式和單位，清楚列出計算過程，最後答案要有正確單位。

### 4.3 試算表基本概念

- 儲存格位址 = 欄字母 + 列數字，例如 B7、AK51。
- **公式必須以「=」開始。**
- 儲存格格式影響顯示及儲存的內容。例如輸入 000815，數值格式會變成 815；學生編號、電話號碼等有前導零的資料應設為**文字**格式。
- 自動填滿可以複製內容，或延伸數列（如日期、編號）。

**運算符**

| 類別 | 運算符 |
|---|---|
| 算術 | `+ - * / ^ %` |
| 比較 | `= <> > >= < <=` |
| 文字串連 | `&` |
| 參照 | `:`（範圍，例如 A1:B10）、`,`（聯合，例如 A1:A5, D2:D6） |

⚠ 比較運算符只可以寫 `<=`、`>=`、`<>`，不可以寫 ≤、≥、≠、=<〔2023 卷一乙 2(a)〕。

### 4.4 儲存格參照

| 類型 | 寫法 | 複製公式時 |
|---|---|---|
| 相對參照 | A1 | 欄和列都按移動距離改變 |
| 絕對參照 | $A$1 | 欄和列都不變 |
| 混合參照 | $A1 或 A$1 | 有「$」的部分不變 |

**複製規則**：先計算目標儲存格與原儲存格相差多少欄、多少列，每個沒有「$」的部分都按相同距離移動。

例子：C3 的公式是 `=A$1+$B2`，複製到 E5（向右 2 欄、向下 2 列）後變成 `=C$1+$B4`。

參照其他工作表：`='工作表名稱'!B3`；參照其他檔案：`='[檔案名稱.xlsx]工作表名稱'!B3`。

✔ **公式應參照儲存格，不要把數值直接寫進公式。** 例如佣金率放在 B2，公式寫 `=C6*B$2`；日後佣金率改變，只須修改 B2，所有公式自動更新。

### 4.5 常用函數

**統計函數**

| 函數 | 作用 | 例子 |
|---|---|---|
| SUM(範圍) | 總和 | =SUM(B2:B9) |
| AVERAGE(範圍) | 平均值 | =AVERAGE(C2:E2) |
| MAX(範圍)、MIN(範圍) | 最大值、最小值 | =MAX(F2:F36) |
| COUNT(範圍) | 範圍內**數值**儲存格的數目 | =COUNT(B2:B9) |
| COUNTIF(範圍, 條件) | 符合條件的儲存格數目 | =COUNTIF(B2:B9,"缺席") |
| SUMIF(範圍, 條件, 相加範圍) | 符合條件的對應數值總和 | =SUMIF(C2:C9,"4A",D2:D9) |
| RANK(數值, 範圍, [次序]) | 排名；次序省略或 0 為遞減，非 0 為遞增 | =RANK(B2,B$2:B$9) |

條件中可以用萬用字元：`*` 代表任何數目的字符，`?` 代表一個字符，例如 "4?" 代表所有中四班別。

**數學函數**：ROUND(X, D) 四捨五入至 D 位小數；INT(X) 取不大於 X 的最大整數，例如 INT(−4.3) = −5；SQRT(X) 平方根；RAND() 傳回 0 至小於 1 的隨機數。

**邏輯函數**：IF(條件, 真值, 假值)；AND(條件 1, 條件 2, …) 全部成立才傳回 TRUE；OR(…) 任何一個成立即傳回 TRUE；NOT(條件) 取相反。

巢狀 IF 例子：`=IF(B2>=80,"A",IF(B2>=50,"B","C"))`

**文字函數**

| 函數 | 作用 | 例子（A1 = "Banana"） |
|---|---|---|
| LEN(文字) | 字符數目（空格也計算） | =LEN(A1) → 6 |
| LEFT(文字, N) | 最左 N 個字符 | =LEFT(A1,3) → Ban |
| RIGHT(文字, N) | 最右 N 個字符 | =RIGHT(A1,4) → nana |
| MID(文字, S, N) | 由第 S 個字符起取 N 個 | =MID(A1,3,2) → na |
| FIND(找甚麼, 文字, [起點]) | 首次出現的位置，區分大小寫 | =FIND("a",A1,3) → 4 |

以 `&` 連接文字：`=LEFT(B2,1)&". "&A2`

**XLOOKUP**

`=XLOOKUP(查找值, 查找範圍, 傳回範圍, [找不到時傳回], [比對模式], [搜尋模式])`

| 比對模式 | 意思 | 典型用途 |
|---|---|---|
| 0（預設） | 完全符合 | 按編號查名稱 |
| −1 | 完全符合，否則取**較小**的最接近值 | 按分數查等級（分數下限表） |
| 1 | 完全符合，否則取**較大**的最接近值 | 按人數找容量足夠的旅遊巴 |

例子：分數在 F2，等級表下限在 J2:J6、等級在 K2:K6，公式為 `=XLOOKUP(F2,$J$2:$J$6,$K$2:$K$6,,-1)`。

### 4.6 試算表公式：考評局常見失分

> ⚠ **〔2025 卷一乙 1(a)〕在 F2 輸入公式計算三次測驗的平均分，再複製到 F3:F36。**
> ✔ `=AVERAGE(C2:E2)`；`=SUM(C2:E2)/3` 等方法亦接受。
> ✘ 常見錯誤是寫成 **AVG**（那是 SQL 的函數）。注意「=」號。

> ⚠ **〔2025 卷一乙 1(b)〕在 H2 輸入公式，計算平均分少於或等於 G2 的學生人數，再複製到 H3:H6。**
> ✔ `=COUNTIF($F$2:$F$36,"<="&G2)`
> ✘ 考生表現「尚可」。不少人寫 `"<=G2"`，或漏了 `&`。一位第 5 級考生寫 `'<=G2'`，同樣失分。
> 要點：比較符號放在引號內，用 `&` 連接儲存格參照；引號外的 G2 才會取儲存格的值。統計範圍要用絕對參照。

> ⚠ **〔2024 卷一乙 1(a)(i)〕D 欄或 E 欄任何一個是 1，F 欄顯示 1，否則顯示 0。**
> ✔ `=IF(D2+E2>=1,1,0)`；條件亦可寫 `D2+E2>0`、`OR(D2=1,E2=1)`；或寫 `=IF(D2+E2=0,0,1)`。
> ✘ 真假值寫成 `"1","0"`（加了引號就變成文字，不是數值）；`OR(D2,E2)=1`。

> ⚠ **〔2024 卷一乙 1(a)(ii)〕B85 的公式 `=SUMIF(A2:A81,"S01",F2:F81)` 結果正確，但複製到 B86、E85、E86 後出錯。改正 B85 的公式。**
> ✔ `=SUMIF($A$2:$A$81,A85,$F$2:$F$81)`
> 要點：兩個範圍都要**絕對參照**；條件改為參照**儲存格 A85**，而且要用**相對參照**，複製到 E85 時才會變成 D85。
> ✘ `$A85`（複製到 E 欄時仍然參照 A 欄）；`"S01"`（寫死了條件）；範圍沒有加 $。

> ⚠ **〔2023 卷一乙 2(a)(b)〕**
> ✔ `=IF($C2<=$C$102,1,0)`；`=$D2*$E2+$E$102`
> ✘ 大部分考生懂得用 IF，但很多人失去第二分：符號寫成 ≤、漏了「=」、把條件或數值放入引號；另有考生沒有在 E$102 加 $。

考評局 2024 年的教學建議：注意公式語法；**數值不可加引號等標點**；正確使用 $；**函數名稱不可串錯**。

### 4.7 排序與篩選

- **排序（sort）**：按一個或多個鍵重新排列記錄，會改變記錄的次序。多鍵排序先按**主要鍵**，主要鍵相同時再按**次要鍵**。
- **篩選（filter）**：只顯示符合條件的記錄，其餘暫時隱藏，**不改變原始數據**；取消篩選後全部重現。

> ⚠ **〔2024 卷一乙 1(a)(iv)〕記錄已排序，寫出排序方式。**
> ✔ 首先按 DATE **遞減**，再按 NAME **遞增**。要從數據推斷：日期由 2024-02-28 排到 2024-02-27，同一日內姓名按字母次序。
> ✘ 次序顛倒（先 NAME 後 DATE），或遞增、遞減寫錯。

✔ 要找「信社學生，按分數由高至低」：先設篩選條件「學社 = 信」，再按分數遞減排序。

### 4.8 圖表、樞紐分析表與假設分析

**圖表類型**

| 圖表 | 用途 |
|---|---|
| 直條圖、橫條圖 | 比較不同類別的數值 |
| 折線圖 | 顯示隨時間變化的趨勢 |
| 圓形圖 | 顯示各部分佔整體的比例 |
| 散點圖 | 顯示兩組數據的相關性 |
| 雷達圖 | 同時比較多項指標 |

圖表元素：圖表標題、X 軸及 Y 軸標題、圖例、數據標籤、網格線。圓形圖沒有座標軸。2D 圖表比 3D 圖表更能準確反映數值比例。

> ⚠ **〔2023 卷一乙 2(e)〕以圖表展示分數最高的 5 位學生。**
> ✔ 選擇合適的圖表類型（直條圖，1 分），並標示圖表標題、座標軸標題、數據標籤或圖例中的兩項（2 分）。
> ✘ 有考生畫了**表格**而不是圖表；有考生只為一條軸加上名稱或數據標籤。

**樞紐分析表（pivot table）**從大量數據建立摘要表，由四部分組成：**列標籤、欄標籤、值、報表篩選**。「值」可以選 SUM、COUNT、AVERAGE、MAX、MIN。**樞紐分析圖**以圖表形式顯示樞紐分析表。

例子：數據表有「班別、學社、分數」三欄，要製作「各學社在各班取得的總分」：列標籤 = 學社，欄標籤 = 班別，值 = 分數的總和。

> ⚠ **〔2023 卷一乙 2(c)〕完成樞紐分析表的設定，求每位學生的分數總和。**
> ✔ 欄 = StudID；值 = **Sum of Score**（加總 Score）。
> ✘ 很多考生只寫 Score 而沒有指明 **SUM**；把欄名寫錯（如 Scores）；加入了多餘的欄位。

**假設分析（What-If Analysis）**：改變輸入數值，觀察對結果的影響，用於預測和規劃。工具包括分析藍本管理員（Scenario Manager）和目標搜尋（Goal Seek）。

✔ 區分：假設分析是比較**不同的輸入數據組合**；樞紐分析表是把**同一組數據**分類摘要。「改變不同參數估算每月支出」適合假設分析；「比較各分店銷售」屬樞紐分析或圖表〔樣本試卷甲部第 8 題〕。

✔ 試算表適合小型數據分析和圖表製作；DBMS 適合大量結構化數據、多人存取及存取權限控制。試算表不宜直接分析大數據，因為工作表可容納的列數有限，處理大量數據時效率低〔樣本試卷乙部 2(b)〕。

### 4.9 數據庫：表單、查詢、報表與數據表設計

| 項目 | 作用 |
|---|---|
| 數據表（table） | 以列（記錄）和欄（欄位）儲存數據；是數據庫必須具備的項目 |
| 表單（form） | 輸入、顯示、修改記錄的圖形介面 |
| 查詢（query） | 從一個或多個數據表提取符合條件的數據，可以計算和排序；可以儲存再用 |
| 報表（report） | 按預設格式在屏幕顯示或列印，常用於摘要，例如成績表 |

**使用表單的好處**：提供方便的輸入環境（簡化使用者介面）；可設定有效性檢驗，例如範圍檢查；可設定數據驗證，例如輸入兩次密碼；以下拉式選單、單選按鈕、核取方塊、日期選擇器簡化輸入；一個表單可以同時修改多個數據表的相關記錄。

⚠ 表單**不能**縮短 SQL 執行時間，也**不會**減少儲存空間〔改編自 2021 卷一甲第 11 題〕。

**設計數據表的步驟**：列出需要記錄的項目 → 每個項目設為一個欄位 → 起一個簡短而有意義的欄名 → 決定數據類型和欄位長度 → 設定主關鍵碼 → 視乎需要加入有效性檢驗規則。

| 數據類型 | 用途 | 例子 |
|---|---|---|
| 文字／字符 | 名稱、編號、電話號碼（不作計算） | NAME、TEL_NO、HKID |
| 整數 | 需要計算的整數 | AGE、MARK |
| 浮點數（實數） | 有小數的數值 | PRICE、AREA |
| 日期／時間 | 日期 | DOB |
| 布爾 | 是／否 | PAID |

✔ 電話號碼、學生編號用文字類型：不會拿來計算，而且可能有前導零或字母。
✔ 日期用日期類型：方便排序、篩選和計算日數。若用文字，「10/2/2025」會排在「2/2/2025」之前。
✔ 欄位長度要足夠但不浪費，例如英文姓名 20 以上，中文姓名 4 左右。

### 4.10 SQL SELECT 語句

**書寫次序**

```sql
SELECT   欄位或運算式
FROM     數據表
WHERE    篩選記錄的條件      -- 分組前篩選
GROUP BY 分組欄位
HAVING   篩選組別的條件      -- 分組後篩選
ORDER BY 排序欄位 [ASC | DESC]
```

**示例數據表 LOAN（自擬）**

| SID | CLASS | BOOK | DAYS |
|---|---|---|---|
| S01 | 4A | B12 | 7 |
| S02 | 4B | B05 | 14 |
| S01 | 4A | B33 | 3 |
| S03 | 4A | B12 | 10 |
| S04 | 4C | B08 | 21 |

| SQL | 輸出 | 說明 |
|---|---|---|
| `SELECT SID, DAYS FROM LOAN WHERE CLASS = '4A' AND DAYS > 5` | S01 7<br>S03 10 | AND：兩個條件都要成立 |
| `SELECT COUNT(*) FROM LOAN WHERE DAYS BETWEEN 7 AND 14` | 3 | BETWEEN 包括兩端的值（7、14、10） |
| `SELECT DISTINCT BOOK FROM LOAN WHERE BOOK LIKE 'B_2'` | B12 | `_` 代表一個字符；DISTINCT 刪除重複 |
| `SELECT SID, COUNT(*) FROM LOAN GROUP BY SID HAVING COUNT(*) > 1` | S01 2 | 先分組，再篩選組別 |
| `SELECT CLASS, SUM(DAYS) FROM LOAN GROUP BY CLASS ORDER BY SUM(DAYS) DESC` | 4C 21<br>4A 20<br>4B 14 | 每組一行；按總數遞減 |

**運算符及關鍵字**

| 項目 | 用法 |
|---|---|
| 比較 | `= < <= > >= <>` |
| 邏輯 | AND、OR、NOT；優先次序 NOT > AND > OR，不肯定時加括號 |
| `LIKE` | `%` 代表零個或多個字符，`_` 代表一個字符，例如 `NAME LIKE 'J%'` |
| `BETWEEN a AND b` | 介乎 a 與 b，包括 a 和 b |
| `IS NULL` | 欄位是空值（不可寫 `= NULL`） |
| `IN (…)` | 等於清單中任何一個值 |
| 集合函數 | SUM、AVG、MAX、MIN、COUNT(*)、COUNT(欄位)（不計空值） |
| `AS` | 為輸出欄位定別名，例如 `SUM(DAYS) AS TOTAL` |
| `ORDER BY` | 預設遞增（ASC）；DESC 遞減；可按多個欄位排序 |

**追蹤 GROUP BY 輸出的步驟**

1. 先用 WHERE 剔除不符合條件的記錄。
2. 把餘下記錄按 GROUP BY 欄位分組，**每組只輸出一行**。
3. 對每組計算集合函數。
4. 用 HAVING 剔除不符合條件的組別。
5. 按 ORDER BY 排序；沒有 ORDER BY 時，考評局一般不要求特定次序。

> ⚠ **〔2024 卷一乙 1(b)(iii)〕根據首 8 個記錄，寫出以下 SQL 的輸出。**
> `SELECT EID, COUNT(*) FROM ATTEND WHERE SIGNIN + SIGNOUT = 1 GROUP BY EID HAVING COUNT(*) > 1`
> ✔ S03 2、S04 2（次序不拘）。
> ✘ 列出了不符合 HAVING 條件的組別（如 S01 1），或列出 COUNT 為 0 的員工；把 S03、S04 寫在同一行。

> ⚠ **〔2023 卷一乙 2(d)(ii)〕** SUM 配合 GROUP BY：部分考生沒有把兩個 S01 記錄合成一組，或沒有把 4 和 6 相加得 10。

> ✔ **〔2025 卷一乙 7(d)〕** `SELECT CL, CNO FROM SS WHERE SER = '賣旗' AND CL LIKE '2_'`，以及 `SELECT CL, SUM(HR) FROM SS GROUP BY CL`。考生表現「很好」，這類題目必須取分。

**SQL 失分清單**（整理自 2024、2025 年簡報，包括選修二甲的評卷原則）

- ✘ 集合函數放在 WHERE 內，例如 `WHERE DAYS > AVG(DAYS)`。集合函數只可以用於 SELECT 或 HAVING。
- ✘ 數值加上引號，例如 `YEAR = '2012'`（應寫 `YEAR = 2012`）；文字則必須加引號，例如 `CLASS = '4A'`。
- ✘ 用 ≤ 代替 `<=`。
- ✘ 子句次序錯誤，例如 ORDER BY 放在 WHERE 條件中間。
- ✘ SELECT 了不在 GROUP BY 中、又不是集合函數的欄位。
- ✘ 把 SQL 的 AVG 寫進試算表，或把試算表的 AVERAGE 寫進 SQL。

### 4.11 自我檢測

<details><summary>1. B2 的公式是 =$A2*B$1。複製到 D5 後，公式是甚麼？</summary>

向右 2 欄、向下 3 列：$A2 → **$A5**；B$1 → **D$1**。答案：`=$A5*D$1`。
</details>

<details><summary>2. A2:A100 是班別，C2:C100 是分數。寫出計算 4B 班總分的公式，以及 4B 班人數的公式。</summary>

總分：`=SUMIF(A2:A100,"4B",C2:C100)`；人數：`=COUNTIF(A2:A100,"4B")`。
</details>

<details><summary>3. 根據上文 LOAN 表，寫出 SQL 找出每班借書的平均日數，只列出平均日數超過 10 的班別。</summary>

`SELECT CLASS, AVG(DAYS) FROM LOAN GROUP BY CLASS HAVING AVG(DAYS) > 10`
輸出：4B 14、4C 21（4A 的平均是 20 ÷ 3 ≈ 6.67，不符合條件）。
</details>

<details><summary>4. 某同學寫 =IF(A2>=50,"1","0")，再以 =SUM(B2:B30) 計算合格人數，結果是 0。為甚麼？</summary>

"1" 和 "0" 加了引號，是文字而不是數值，SUM 不會把文字相加。應寫 `=IF(A2>=50,1,0)`。
</details>
