卷二分為甲部（數據庫）、乙部（網絡應用程式開發）和丙部（算法與程式編寫），考生選答其中兩部的全部試題。2025 年甲部共五題，題型包括繪畫實體關係圖、寫 SQL、追蹤 SQL 的輸出、規範化和概念題。

本選項建基於必修單元 A 的「數據組織及數據控制」和「數據操縱和分析」：單元 A 只要求在單一數據表中查詢，本選項延伸至最多三個數據表、修改數據和數據表結構，以及數據庫設計。三個課題如下：

| 課題 | 課時 | 對應課本章節 |
|---|---|---|
| a. 關聯式數據庫概念 | 6 | 第 1 章 |
| b. 結構化查詢語言 | **18** | 第 2、3 章 |
| c. 數據庫設計方法 | 14 | 第 4、5 章 |

SQL 佔本選項近一半課時，每年甲部都有多條要寫 SQL 的分題；實體關係圖和規範化亦幾乎每年都考。考評局的評論反覆指出三個弱點：子查詢與 GROUP BY／HAVING、實體關係圖的最少數目（參與限制）、規範化時寫錯主關鍵碼和外鍵碼。

## 考前一頁清單

**關聯式數據庫概念**
- [ ] 實體、實例、屬性、關係、域、空值的意思，並能從日常應用中舉例
- [ ] 候選鍵碼可以有多個；主關鍵碼從中選出，獨一無二、不可為空值；外鍵碼參照另一數據表（或同一數據表）的主關鍵碼
- [ ] 複合鍵碼以「+」連接，例如 `MID + BID + BDATE`；要包含足夠的欄位，但不要有多餘欄位
- [ ] 有前導零或字母的編號用字符類型，並寫出原因
- [ ] 索引加快搜尋，但佔用空間、減慢插入和更新；`CREATE INDEX 名稱 ON 數據表 (欄位1, 欄位2)`，先列 WHERE 欄位，再列 ORDER BY 欄位
- [ ] 實體完整性（主關鍵碼重複或空值）、參照完整性（外鍵碼不存在）、域完整性（數值無效或超出範圍）；答題先寫類別，再寫原因
- [ ] 回滾撤銷未提交的交易，令數據庫回復到之前的狀態；已提交的數據損毀要靠備份

**結構化查詢語言**
- [ ] `ALTER TABLE … ADD`、`ALTER COLUMN`、`DROP COLUMN`；`DELETE FROM` 刪記錄，`DROP TABLE` 刪整個數據表
- [ ] `INSERT INTO … VALUES (…)` 跟數據表的欄位次序；數值不加引號，文字和日期加引號
- [ ] `UPDATE … SET 欄位 = 欄位 + 10 WHERE …`；UPDATE 和 DELETE 漏寫 WHERE 會影響所有記錄
- [ ] AND 先於 OR，不肯定時加括號；BETWEEN 包括兩端；LIKE 的 `%` 和 `_`；`IS NULL`
- [ ] `COUNT(*)` 與 `COUNT(欄位)` 的分別；`SUBSTRING(s, 起點, 長度)` 由 1 起計
- [ ] WHERE 在分組前篩選記錄，HAVING 在分組後篩選組別；聚合函數不可放在 WHERE
- [ ] 連接 n 個數據表要 n − 1 個連接條件；同名欄位寫成「數據表.欄位」；需要時加 DISTINCT
- [ ] 找出沒有配對的記錄：`LEFT JOIN … WHERE 右表.欄位 IS NULL`，或 `NOT IN (子查詢)`
- [ ] 與最大值、平均值比較要用子查詢：`WHERE PRICE = (SELECT MAX(PRICE) FROM …)`
- [ ] `> ANY` 即大於最小值，`> ALL` 即大於最大值；EXISTS 檢查子查詢有沒有記錄
- [ ] UNION 刪除重複的行，UNION ALL 保留；INTERSECT 取兩邊都有的；MINUS 取第一句有而第二句沒有的
- [ ] 檢視是虛擬數據表：簡化查詢、先計算再比較、隱藏敏感數據

**數據庫設計方法**
- [ ] 實體旁的符號描述「另一方每個實例對應多少個這個實體」：1 或 M 是最多，| 或 O 是最少
- [ ] 每個關係兩端都要有基數和參與限制，不要遺漏題目描述的關係
- [ ] 分解多對多：加入關聯實體，兩邊改為一對多，原本兩實體旁都是 1 和 |，原本的參與限制互換位置放在關聯實體兩旁
- [ ] 插入異常、更新異常、刪除異常各舉一例；數據冗餘要指明哪個欄位在甚麼情況下重複
- [ ] 衍生屬性可由其他屬性計算，例如年齡、求診次數；HKID 不是衍生屬性
- [ ] 1NF：原子值、沒有重複組；2NF：沒有部分依賴；3NF：沒有傳遞依賴
- [ ] 規範化的答案要寫齊每個數據表的欄位、主關鍵碼和外鍵碼；留意同一編號在不同組別重複時要用複合鍵碼
- [ ] 非規範化：合併數據表、加入冗餘欄位或衍生屬性、使用檢視；好處是查詢較快，壞處是冗餘和不一致；「節省儲存空間」不是好處
- [ ] 實體關係圖轉數據表：一對多把「1」方的主關鍵碼放入「M」方；多對多的關聯實體成為數據表
- [ ] 存取權限按角色和層次（數據庫、數據表、記錄、欄位）設定；以檢視隱藏欄位和記錄；個人資料用於其他用途要先取得同意
