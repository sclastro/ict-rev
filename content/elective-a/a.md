## 1.1 課程要求

描述關聯式數據庫的基本概念，包括實體、關係、屬性、域、索引、鍵碼（主關鍵碼、外鍵碼、候選鍵碼）和完整性（實體完整性、參照完整性、域完整性），並能從日常應用例子中辨別關聯式數據庫的基本元素；建立簡單的關聯式數據庫，以不同但合理的方式組織數據，並在數據表之間建立所需的關係；描述回滾的目的。

本課題延伸自單元 A 課題 b「數據組織及數據控制」。數據的分級組織、主關鍵碼的基本要求和有效性檢驗，見[單元 A 課題 b](../core-a/b.html) 的 2.3 至 2.8 節；本頁不再重複。

## 1.2 數據庫與關聯式數據庫

**數據庫**是有組織、相互關聯的數據集合。**數據庫管理系統**（DBMS）是建立、維護和存取數據庫的軟件，負責控制誰可以存取數據、檢查數據是否符合規則、備份和復原數據等。**關聯式數據庫**把數據存放在多個**數據表**中，數據表之間以鍵碼連結。

| 用語 | 意思 | 例子（學生數據表） |
|---|---|---|
| 數據表（table） | 描述同一類事物的記錄集合，以行和列排列 | STUDENT |
| 記錄（record） | 數據表中的一行，描述一個實例 | 學生 S2401 的全部資料 |
| 欄位（field） | 數據表中的一列，描述一項特性 | NAME、DOB |

考評局的中文試卷有時把數據表寫成「數據庫表」，課程文件則稱為「資料表」，三者意思相同。

**為甚麼用多個數據表，而不把所有資料放在一個表內？** 以學校借書為例，若把學生姓名、班別與每次借書的資料放在同一個表，學生每借一本書，姓名和班別便重複儲存一次。分開成「學生」和「借閱記錄」兩個數據表，再以學生編號連結，每名學生的資料只儲存一次：

- 減少數據冗餘，節省儲存空間；
- 修改學生資料時只改一處，避免前後不一致；
- 未借過書的學生也可以有記錄。

數據冗餘和規範化的詳細內容，見[課題 c](c.html) 的 3.7 至 3.9 節。

## 1.3 實體、屬性、關係與域

| 概念 | 意思 | 例子（圖書館系統） |
|---|---|---|
| 實體（entity） | 需要儲存資料的人、物件、地點或事件；同一類的實體組成一個數據表 | 會員、書籍、借閱 |
| 實例（instance） | 實體中的一個個體，即數據表中的一個記錄 | 會員陳大文 |
| 屬性（attribute） | 描述實體的特性，即數據表中的欄位 | 會員編號、姓名、電話 |
| 關係（relationship） | 實體之間的聯繫 | 會員「借閱」書籍 |
| 域（domain） | 一個屬性所有可接受的值 | 會員類別只可以是 A（成人）或 J（小童）；月份只可以是 1 至 12 |

實體可以是實物（學生、電腦），也可以是概念或事件（訂單、付款、考試成績）。

**空值**（NULL）表示該欄位沒有數值或數值未知，與 0 和空字串都不同。例如還未歸還的借閱記錄，「歸還日期」為空值。

**從日常應用辨別基本元素**：分析一個系統時，先找出要記錄的「事物」（實體），再寫出每項事物要記錄的資料（屬性），然後找出事物之間的聯繫（關係）。例如網上購物平台有「顧客」「產品」「訂單」三個實體；「訂單」的屬性包括訂單編號、訂購日期、數量；關係包括顧客「提交」訂單、訂單「包含」產品。

## 1.4 鍵碼

| 鍵碼 | 意思 | 例子 |
|---|---|---|
| 候選鍵碼（candidate key） | 可以唯一識別每個記錄的欄位或最少欄位組合；一個數據表可以有多個 | 員工數據表中的員工編號、香港身份證號碼 |
| 主關鍵碼（primary key） | 從候選鍵碼中選定一個，用來識別記錄；數值必須獨一無二，不可為空值 | 員工編號 |
| 複合鍵碼（composite key） | 由兩個或以上欄位組成的主關鍵碼 | 借閱記錄的「會員編號 + 書籍編號 + 借閱日期」 |
| 外鍵碼（foreign key） | 一個數據表中參照另一個數據表主關鍵碼的欄位，用來連結兩個數據表 | 借閱記錄中的會員編號，參照會員數據表的會員編號 |

**選擇主關鍵碼**：從候選鍵碼中選最少欄位、數值不會改變、不涉及敏感個人資料的一個。香港身份證號碼雖然獨一無二，但屬敏感個人資料，而且部分人（例如非本地學生）未必持有，一般不宜作主關鍵碼；姓名可能重複，不能作主關鍵碼。

**外鍵碼可以參照同一個數據表**。例如會員數據表的 REFER 欄位儲存介紹人的會員編號〔2023 卷二甲 1〕，學生數據表的 LEADER 欄位儲存組長的學生編號〔2024 卷二甲 4〕。外鍵碼可以是空值（例如沒有介紹人），但不是空值時，必須是數據表中已有的主關鍵碼值。

> ⚠ **〔2024 卷二甲 1(a)〕STAFF 數據表有 SID（員工編號）、HKID（身份證號碼）、SNAME（姓名）、DEPT（部門），主關鍵碼為 SID。寫出 SID 以外的一個候選鍵碼。**
> ✔ HKID。考評局評為「極佳」，幾乎所有考生答對。SNAME 不可以，因為姓名可能重複。

> ⚠ **〔2012 練習卷卷二甲 1(a)(ii)〕考生數據表 CAND 有 CNUM（考生編號）、CNAME（姓名）、DOB（出生日期）。CNUM 和 CNAME + DOB，哪一個可以作候選鍵碼？**
> ✔ CNUM，因為它是獨一無二的。CNAME + DOB 不保證獨一無二：兩名考生可能同名而且同日出生。

**複合鍵碼要包含足夠的欄位**。若同一會員可以在不同日子借同一本書，「會員編號 + 書籍編號」會重複，必須加入借閱日期。寫複合鍵碼時，評卷參考以「+」連接欄位，例如 `MID + BID + BDATE`。

## 1.5 數據類型

設計數據表時，每個欄位都要選定數據類型和長度。考評局試題常用的數據類型如下：

| 數據類型 | SQL 寫法 | 用途 | 例子 |
|---|---|---|---|
| 字符 | `CHAR(n)`、`VARCHAR(n)` | 名稱、編號、電話號碼等不作計算的數據 | 學生編號、HKID |
| 整數 | `INTEGER` | 需要計算的整數 | 數量、年份 |
| 數值（實數） | `NUMERIC`、`REAL` | 有小數的數值 | 價格 |
| 日期 | `DATE` | 日期，方便比較、排序和計算 | 出生日期 |
| 布爾 | `BOOLEAN` | 只有兩個值 | 是否已付款 |

`CHAR(n)` 是固定長度，`VARCHAR(n)` 是可變長度，兩者的 n 都是最大字符數。

**編號用字符類型**：學生編號、客戶編號等可能以 0 開頭（例如 00018），也可能包含字母，而且不用來計算。若用整數類型，前導零會消失。

> ⚠ **〔2025 卷二甲 5(a)〕訂房記錄中客人編號 GID 的例子是 00018。寫出 GID 的數據類型，並簡略解釋。**
> ✔ 字符，因為客人編號包含前導零。
> ✘ 只寫「字符」而沒有解釋，不給分。〔2024 卷二甲 4(a)〕同類題目中，較弱的考生未能認出要用字符類型保留前導零。

**存放數值的欄位用數值類型**：例如分數、數量需要計算平均值或總和，應用整數或數值類型，同時可以限制輸入的值必須是數字。

## 1.6 索引

**索引**（index）是數據庫為一個或多個欄位另外建立的排序目錄，記錄每個值在數據表中的位置，作用類似書末的索引。

| | 說明 |
|---|---|
| 好處 | 按索引欄位搜尋、篩選、排序或連接數據表時，毋須逐個記錄檢查，速度較快 |
| 代價 | 索引要佔用額外儲存空間；每次新增、刪除或修改記錄，數據庫都要同時更新索引，這些操作會變慢 |
| 適合建立索引的欄位 | 經常用於 WHERE 條件、ORDER BY 排序或連接的欄位，例如主關鍵碼和外鍵碼 |

建立和刪除索引的 SQL：

```sql
CREATE INDEX SHOWTIME ON TINFO (CID, MTIME)
DROP INDEX SHOWTIME ON TINFO
```

> ⚠ **〔2023 卷二甲 4(b)(ii)、(iii)〕為 TINFO 的 CID 和 MTIME 建立名為 SHOWTIME 的索引，並寫出一個好處。**
> ✔ `CREATE INDEX SHOWTIME ON TINFO (CID, MTIME)`；好處是搜尋更有效率，所需時間較短。
> ✘ 考評局指出，只有約三分之一考生寫出正確的 CREATE INDEX 語句。

> ⚠ **〔2024 卷二甲 3(c)(i)〕`SELECT MNAME, SEX, DOB FROM MEMBER WHERE DOB > '1/1/1988' ORDER BY MNAME`。從 MNAME、SEX、DOB 選兩個欄位建立索引 MINDEX，令這句 SQL 的效能最好。**
> ✔ `CREATE INDEX MINDEX ON MEMBER (DOB, MNAME)`：先列用於 WHERE 篩選的 DOB，再列用於 ORDER BY 排序的 MNAME。
> ✘ 寫成 `(MNAME, DOB)` 只得一分。考評局指出，考生普遍不熟悉建立索引時欄位的次序。

> ⚠ **〔2024 卷二甲 3(c)(iii)〕MID 已建立索引。要把會員 00083 的姓名改為 Chan Tai Man，為何「先 DELETE 再 INSERT」會令數據庫重建索引？**
> ✔ 因為這個方法涉及刪除和新增記錄，數據庫要從索引移除舊記錄、再加入新記錄；只用 UPDATE 修改 MNAME 則不會影響 MID 的索引。考評局指出，較弱的考生未能解釋這一點。

## 1.7 數據完整性

**數據完整性**指數據庫中的數據準確、一致而且有效。關聯式數據庫有三種完整性規則：

| 完整性 | 規則 | 違反的例子 | 以甚麼約束實現 |
|---|---|---|---|
| 實體完整性（entity integrity） | 每個記錄的主關鍵碼必須獨一無二，而且不可為空值 | 新增一個員工編號已存在的記錄；主關鍵碼留空 | `PRIMARY KEY` |
| 參照完整性（referential integrity） | 外鍵碼的值必須是所參照數據表中已有的主關鍵碼值（或是空值） | 借閱記錄的會員編號在會員數據表中不存在；刪除仍有借閱記錄的會員 | `FOREIGN KEY … REFERENCES …` |
| 域完整性（domain integrity） | 欄位的值必須屬於該欄位的域：數據類型、長度、範圍、格式都要正確 | 日期 30/2/2022；分數 -5；月份 13 | 數據類型、`NOT NULL`、`CHECK`、`UNIQUE` |

`NOT NULL` 規定欄位不可為空值，`UNIQUE` 規定欄位的值不可重複。`CHECK` 可以限制範圍，例如 `CHECK (MARK BETWEEN 0 AND 100)`；它不在考評局的 SQL 清單內，答題時可以用文字描述「範圍檢查」。

> ⚠ **〔2024 卷二甲 4(c)〕D1 數據表的主關鍵碼為 SID，LEADER 是參照同一數據表 SID 的外鍵碼。以下每個新記錄都會引致完整性問題，寫出問題並解釋。(i) SID 為 012345（已存在）；(ii) 登記日期為 30/2/2022；(iii) LEADER 為 023456（數據表中沒有這名學生）。**
> ✔ (i) 實體完整性：SID 是主關鍵碼，012345 在 D1 中重複；(ii) 域完整性：日期無效，超出範圍；(iii) 參照完整性：組長的編號在 D1 中不存在。每部分先寫完整性的類別，再寫原因。
> ✘ 考評局指出，不少考生只答對一兩部分，未能清楚分辨三種完整性問題。

> ⚠ **〔2023 卷二甲 2(b)〕為以下輸入錯誤寫出適當的數據庫約束：PREF1（選科優先次序 1 至 3）輸入了 9；YR（整數）輸入了 "YY22"；SNO（學生編號）是空值。**
> ✔ PREF1：數據範圍；YR：數據類型；SNO：主關鍵碼／非空值（NOT NULL）。
> ✘ 考評局指出，大部分考生未能寫出 SNO 的約束；較弱的考生把「數據格式」當作約束。

> ⚠ **〔2025 卷二甲 5(d)〕`INSERT INTO BK VALUES ("B88332211", "R0068", "12345", "15-8-2025", "12-8-2025")`，最後兩個值分別是入住和退房日期。為何這句 SQL 會引致完整性問題？**
> ✔ 入住日期比退房日期遲，數據無效。考評局評為「良好」。

〔改編自 2025 模擬試卷卷二甲第 2 題〕員工數據表 EMP 的 DEPTID 參照部門數據表 DEPT。若刪除仍有員工的部門記錄，EMP 中這些員工的 DEPTID 便參照一個不存在的部門，違反參照完整性，因此數據庫會拒絕刪除。

部分 DBMS 容許在外鍵碼加上 `ON DELETE CASCADE`：刪除所參照的記錄時，自動一併刪除參照它的記錄。這屬延伸內容。

## 1.8 建立簡單的關聯式數據庫

建立數據表時，以 `CREATE TABLE` 定義欄位、數據類型和約束：

```sql
CREATE TABLE MEMBER (
  MID    CHAR(6) PRIMARY KEY,
  MNAME  VARCHAR(40) NOT NULL,
  MTYPE  CHAR(1),
  JDATE  DATE
)

CREATE TABLE LOAN (
  MID    CHAR(6),
  BID    CHAR(8),
  LDATE  DATE,
  RDATE  DATE,
  PRIMARY KEY (MID, BID, LDATE),
  FOREIGN KEY (MID) REFERENCES MEMBER (MID),
  FOREIGN KEY (BID) REFERENCES BOOK (BID)
)
```

- 單一欄位的主關鍵碼可以寫在欄位後面；複合鍵碼要另起一行寫 `PRIMARY KEY (欄位1, 欄位2, …)`。
- 所參照的數據表（例如 MEMBER、BOOK）要先建立，才可以建立參照它的數據表。
- 未寫 `NOT NULL` 的欄位可以是空值，例如未歸還時的 RDATE。

> ⚠ **〔樣本試卷卷二甲 2(a)〕`CREATE TABLE TRAN (TRANID CHAR(7) ____, TYPE INTEGER, SIZE INTEGER)`。填寫空格，令兩個交易編號相同的記錄不能輸入 TRAN。**
> ✔ `UNIQUE` 或 `PRIMARY KEY`。〔2012 練習卷卷二甲 1(a)(i)〕寫出建立考生數據表的 CREATE TABLE 語句，評卷參考亦同時接受這兩個關鍵字。

**以不同但合理的方式組織數據**：同一批數據可以有多種設計。例如儲物櫃分配可以在學生數據表加入「儲物櫃編號」，也可以在儲物櫃數據表加入「學生編號」；兩者都合理，視乎哪一方的資料較常變動、哪一方容許空值。把數據分成多個數據表後，要以外鍵碼建立數據表之間的關係。由實體關係圖轉換為數據表的方法，見[課題 c](c.html) 的 3.11 節。

## 1.9 交易與回滾

**交易**（transaction）是一組必須全部完成或全部不做的數據庫操作。例如網上轉賬包括「從甲戶口扣款」和「存入乙戶口」兩個步驟；若扣款後系統出錯，存款未完成，便會出現錢不翼而飛的情況。

| 用語 | 作用 |
|---|---|
| 提交（commit） | 交易所有步驟成功後，把改動永久寫入數據庫 |
| 回滾（rollback） | 交易未提交前出錯或要取消時，撤銷交易中已做的改動，令數據庫回復到交易開始前的狀態 |

**回滾的目的**：

- 交易途中出錯（例如系統故障、違反完整性規則、用戶取消）時，撤銷已完成的部分，避免數據庫留下只完成了一半的錯誤數據，保持數據一致；
- 開發和測試數據庫時，可以撤銷測試期間的改動。

**回滾與備份的分別**：回滾只能撤銷**尚未提交**的交易；已提交的數據若因硬件損壞、誤刪或勒索軟件而損毀，要靠**備份**復原。例如老師把全班分數錯誤地扣減了十分並已提交，回滾已不適用，要用 UPDATE 修正或從備份復原。

> ⚠ **〔2025 卷二甲 1(b)〕描述在數據庫管理系統啟用回滾的一個好處。**
> ✔ 交易出錯時（尤其是一個交易包含多個操作時），可以把數據庫回復到之前的狀態；或在開發數據庫時，撤銷測試期間的改動。
> ✘ 考評局指出，考生不熟悉回滾在數據庫管理系統中的作用，較弱的考生寫不出任何好處。

> ⚠ **〔樣本試卷卷二甲 2(b)(ii)〕售鞋網站輸入了一個交易記錄後，發現該款鞋子缺貨，交易取消。數據庫應執行甚麼操作？簡述該操作的目的。**
> ✔ 回滾：撤銷剛才插入的記錄，令數據庫回復到之前的狀態，保持數據一致。

`COMMIT` 和 `ROLLBACK` 不在考評局的 SQL 清單內，考題要求的是描述回滾的作用，不用寫出指令。

**實作建議**：用任何 SQL 系統（例如 MySQL 或 SQLite）建立本頁的 MEMBER 和 LOAN 數據表，嘗試輸入重複的主關鍵碼、不存在的會員編號，觀察數據庫怎樣拒絕違反完整性的數據。MySQL 的日期要寫成 `'2025-03-26'` 的格式，與考評局試卷常見的 `'26-3-2025'` 不同。

## 1.10 自我檢測

<details><summary>1. 解釋「實體」和「屬性」，並以學校圖書館系統各舉一例。</summary>

實體是需要儲存資料的人、物件或事件，例如會員、書籍。屬性是描述實體的特性，例如會員的姓名、書籍的書名。
</details>

<details><summary>2. 甚麼是「域」？舉一個例子。</summary>

域是一個屬性所有可接受的值。例如考試分數的域是 0 至 100 的整數；性別只可以是 M 或 F。
</details>

<details><summary>3. 會員數據表有會員編號、電郵地址、姓名和電話號碼。寫出兩個候選鍵碼，並說明選擇主關鍵碼時要考慮甚麼。</summary>

候選鍵碼：會員編號、電郵地址。選擇主關鍵碼時，要選數值獨一無二、不會為空值、不常改變、不涉及敏感資料而且欄位最少的一個，因此宜選會員編號。（電話號碼可能由家人共用，姓名可能重複，都不宜作候選鍵碼。）
</details>

<details><summary>4. 借閱記錄數據表 LOAN 有 MID、BID、LDATE。為何主關鍵碼要用 MID + BID + LDATE，而不只用 MID + BID？</summary>

同一名會員可以在不同日子借同一本書，MID + BID 會重複，不能唯一識別記錄；加入借閱日期後才獨一無二。
</details>

<details><summary>5. 員工編號的例子是 00057。為何應選用字符類型而不用整數類型？</summary>

員工編號有前導零，若用整數類型會變成 57，前導零消失；而且編號不用來計算。
</details>

<details><summary>6. 寫出建立索引的一個好處和一個壞處。</summary>

好處：按索引欄位搜尋、篩選或排序時速度較快。壞處：佔用額外儲存空間；新增、刪除和修改記錄時，要同時更新索引，速度變慢。
</details>

<details><summary>7. 以下各情況違反哪一種完整性？(a) 新增的訂單記錄中，顧客編號在顧客數據表不存在；(b) 兩個學生記錄的學生編號相同；(c) 出生日期是 31/4/2010。</summary>

(a) 參照完整性；(b) 實體完整性；(c) 域完整性。
</details>

<details><summary>8. 完成以下 SQL，令 DEPTID 參照 DEPT 數據表的 DEPTID：<code>CREATE TABLE EMP (EMPID CHAR(5) PRIMARY KEY, DEPTID CHAR(5), ____ )</code></summary>

`FOREIGN KEY (DEPTID) REFERENCES DEPT (DEPTID)`
</details>

<details><summary>9. 外鍵碼可以是空值嗎？舉例說明。</summary>

可以。例如會員數據表的 REFER（介紹人編號）參照同一數據表的會員編號；沒有介紹人的會員，REFER 為空值。外鍵碼不是空值時，才必須是已存在的主關鍵碼值。
</details>

<details><summary>10. 甚麼是交易？舉例說明為何需要回滾。</summary>

交易是一組必須全部完成或全部不做的操作。例如轉賬時已從甲戶口扣款，但存入乙戶口時系統出錯，便要回滾，撤銷扣款，令數據庫回復到轉賬前的狀態。
</details>

<details><summary>11. 一間公司的檔案遭勒索軟件加密。應使用回滾還是備份復原？為甚麼？</summary>

備份復原。回滾只能撤銷尚未提交的交易；遭加密的數據早已提交，只能從攻擊前的備份復原。
</details>

<details><summary>12. 為何關聯式數據庫把數據分成多個數據表，而不放在一個大數據表內？寫出兩個原因。</summary>

減少數據冗餘，節省儲存空間；修改資料時只需改一處，避免數據不一致；可以獨立儲存某一類資料（例如未借書的會員）。（任何兩項）
</details>
